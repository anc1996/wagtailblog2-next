# ADR-P0-04：公共 Image、Rendition 与 Document

- 日期：2026-10-31
- 状态：公共资源 App 身份、局域网公开交付方向已确认；模型字段/约束、初始结构和交付技术细则仍待验证。
- 证据级别：E1；未创建模型、迁移、桶、对象或资源记录。
- 用户批准：`resources` App 身份及简化公开交付原则已确认；模型/交付技术细则仍未实现或验收。

## 来源与用户已确认

依据旧参考仓库 `说明书/00-产品需求与项目管理/` 的 01、04 U05/U19/U23、08 全文、09 §5/§10.2、10 §12。图片/文档/音视频为公共资源，页面只引用；原件、共享关系和历史受保护。P1 仅公共图片及两个真实测试 Page，文档业务在 P2a；不以测试夹具声称正式 Blog/Guide 已完成。

本轮按 U27～U36、U38 产品确认同步局域网公开图片/附件的简化交付原则，并固定 `resources` label；模型设置、字段约束、迁移和交付实现仍按门禁验证。授权、证据及验收责任按 ADR-P0-01。

## 方案建议：模型与设置候选

| 对象 | 继承候选与设置 | 最小合同 |
|---|---|---|
| `resources.Image` | Wagtail AbstractImage；`WAGTAILIMAGES_IMAGE_MODEL="resources.Image"` | Collection、上传者、标签及原生图片字段；保留原生 chooser 扩展点 |
| `resources.Rendition` | Wagtail AbstractRendition | FK 指向公共 Image；保持原生 image/filter/focal-key 唯一性及预期反向关系 |
| `resources.Document` | Wagtail AbstractDocument；`WAGTAILDOCS_DOCUMENT_MODEL="resources.Document"` | 首次迁移前明确最小身份/结构；P2a 再交文档管理、下载/Range 业务 |

继承 API、字段与约束以选定版本后续审阅及验证为准，本表不构成可直接运行的模型定义。具体包/label 见 [ADR-P0-02](ADR-P0-02.md)、[ADR-P0-03](ADR-P0-03.md)，初始依赖见 [ADR-P0-07](ADR-P0-07.md)。

不设万能 Asset 父表，不保留 BlogImage 作为公共层后备，不安装旧新两套 resources。Page 继续使用原生 `wagtailcore.Page`。音视频第三方接入留 P2a；添加 storage alias 不等于按媒体类型完成路由。

## 资源、版本与删除边界

1. MySQL 管资源元数据、权限关系和引用证据；MinIO 管二进制。原件对象不可覆盖，替换原件生成新资源身份及新对象键；数据库事务不能回滚对象上传。
2. alt/caption/order 等引用语义随所在父 Page/正文完整快照保存；全局资源描述不能替代各引用处描述。
3. 建议普通 Page 封面使用保护性资源 FK；InlinePanel/正文引用依原生 Revision 或 Manifest 保存完整关系。具体 on_delete、序列化与历史重放必须实证，不能只看当前 FK。
4. 原生删除单页与资源回收分离；不得连带清理共享原件、派生图、Mongo 版本或全部历史引用。
5. 首版禁止原件原地替换及资源物理删除，覆盖单条、批量、API/直接 POST、后台动作和服务入口；隐藏按钮不构成保护。后续 GC/回收需另行策略、保留证据及明确操作授权。
6. 引用闭包须覆盖当前 SQL 引用、Revision、Manifest、固定集合、Alias、删除保留证据、未决操作、未绑定预写、导入产物及 Outbox。ReferenceIndex 不自动证明 Markdown/Mongo/全部历史已覆盖。
7. 上传/提交超时先按操作及对象身份对账；不得换键盲重试，不自动物理删除新产物。跨存储路径 Mongo 物理删除必须为零。

## 已确认交付原则与待审技术细则

首版面向局域网：已发布且明确公开的内容及其公开图片/附件，无需普通读者登录即可阅读或获取；复杂逐文件授权不是首版产品要求，不以强制读者登录、逐文件签名或私有桶方案作为公开交付前置。公开交付不扩大 P1 到文档业务，文档仍按 P2a 推进。

草稿、未发布内容、私有资源和后台仍须保护；局域网可达不等于全部公开，不能因部署方便而开放整个媒体目录或桶。Collection 是后台管理边界，不等于前台保密或下载授权；私有页面引用公开图不会自动使其私有，公开引用也不能解密受限原件。受限交付仍需核对资源分类、当前引用、主体/站点/语言/用途及正式/预览资格。

公开/受限分类及实际交付路径尚待实现验证；私有桶或受控交付仅为受限场景的技术候选，不是全站已批准策略。仅在确需签名的受限场景审定签名有效期、缓存寿命及撤销残余窗口；Range 和历史保留按所属阶段审定测试，不扩张首版需求。已经下载的公开副本不能承诺收回；预览凭证不得混入公开共享缓存或日志。

## 待用户批准决定与未验证项

- 资源设置和最小 Image/Rendition/Document 初始结构；Document 业务仍延后，不偷跑 P2a。
- 落实已确认公开/受限原则所需的分类与交付技术方案、桶策略、缓存和历史保留；如需受限签名，再审定签名/撤销窗口。不再把“公开内容无需普通读者登录”或复杂逐文件授权列为首版待选项。
- 未验证：抽象类字段与约束、swappable 解析、后台表单/chooser/Collection 权限、文件/派生存储、直接 URL 防护、引用保护及失败重交。

## 风险与依赖

依赖 ADR-P0-05 的真实 User、ADR-P0-06 的独立 Storage 配置、ADR-P0-07 的 Collection/taggit/User 图，以及 [ADR-P0-08](ADR-P0-08.md) 的 Access/快照合同。风险包括公开 ACL 继承、签名残留、把 SQL 保护误认全历史保护、因原生抽象继承推断无需框架资源迁移、用资源管理员身份绕过前台限制。

## 验证计划、停止与回退

- E1：检查模型/设置/依赖提案与 08 一致；不声称上传或下载通过。
- E2：在获批实施范围内，项目导入前阻断 DB、网络、Storage、任务和子进程，受守卫检查模型关系、唯一约束、已有迁移状态及无 Blog/Mongo/ES 依赖的图片子集；不生成或执行迁移、不连真实服务、不开展 E3，不能真实上传。
- E3：另获 SQL/对象存储等具体目标授权后，按 08 IMG01～IMG16 验上传、两类 Page 共享、独立 alt、rendition、Revision/恢复、chooser、越权直读、删除保护、预览与撤销、未知结果及失败重交；图片切片不需为无关 Mongo/ES 做全量快照。
- 停止：资源标识未定、权限未知、当前/历史引用无法保护、对象目标非空且初始化范围不明，或发现旧业务依赖。
- 回退检查：保留已上传对象与 SQL 引用证据，标记待对账；不得通过删共享对象、Mongo 版本或回滚他人修改来“恢复”。代码回退和数据恢复分别授权。
