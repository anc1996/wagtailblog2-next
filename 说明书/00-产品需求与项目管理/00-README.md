## 当前路线与本轮范围

本项目建设基于 Django/Wagtail 的综合内容管理网站，采用 **Wagtail Core + 公共能力平台 + 内容类型注册 + 可选业务插件**。用户已选择完全独立的新站 Git 仓库；新站独立建模、使用独立数据库与资源命名空间。U27～U36 已确认私人局域网访问、公开资源简单交付、原生后台角色、Blog 字段、相关文章、精选集合、阅读统计、评论、单中文站点和简单备份目标；U38～U39 已确认迁移 B、resources/site_home 基础身份、权限基线和稳定依赖策略。当前仍处于 P0 基础骨架和 E2 无外部 IO 验证阶段，未执行迁移或连接外部服务。旧源码用于保留功能与风险识别，不约束新站表结构。历史数据导入另行立项，旧库及媒体必须保留。

Wagtail 原生 Page、Revision、Workflow、权限和发布生命周期是唯一权威。MongoDB 仅保存可选的不可变外置字段版本，MinIO 保存二进制，ES 是可重建投影，Redis 不承担业务权威。公共能力不依赖某个具体 Page；合理的页面 ParentalKey 关系仍可声明具体父类型。

第二轮风险补强、此前 P0 设计续批、仓库环境确认和最小 `AbstractUser` 方向确认的历史记录分别见 10 §11～14。保留 Django/Wagtail 原生认证、组与权限，不增加会员、支付或业务资料字段；公共 Person 与后台 User 分责，按需关联不自动授权。用户已指定 `conda activate wagtailblog-test`，该环境由新站独占；直接依赖稳定版基线已写入 `pyproject.toml`，并需通过环境验证。数据库、桶、索引和队列的隔离及操作范围仍须单独核对；本批未连接外部服务、建库或迁移。会员付费、支付订单及在线插件市场不属于本期范围。

### 为什么放入 `archive-历史原始文档/`

归档表示“保留、只读、用于追溯”，不表示删除或否定这些材料。03、05、06、07 记录的是旧项目的源码事实、旧路径、旧阶段判断和历史风险；它们对识别风险仍有价值，但不应与新站当前需求、ADR、代码和验收记录混在同一权威层级中。这样可以同时做到：

- 保留历史依据，便于追溯某个判断来自哪里；
- 防止旧仓库路径、旧迁移链、旧完成状态被误当成 `wagtailblog2-next` 的当前事实；
- 明确新站只以本目录中的正式说明书、ADR、代码和 11 号台账作为当前依据；
- 允许后续引用历史材料而不把旧项目变成新仓库的 Git 基础、代码副本或运行依赖。

归档材料不得作为新站的实施指令；如历史材料与当前正式文档冲突，以当前正式文档和用户已确认需求为准。
