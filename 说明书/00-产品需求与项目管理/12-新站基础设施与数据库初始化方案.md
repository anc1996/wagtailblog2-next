## 2. 推荐方案与严格阶段顺序

推荐“新站专属资源与分角色账号，服务按阶段启用”。共享物理主机不是默认许可，共享实例更不能只靠命名约定隔离。

| 顺序 | 阶段与服务 | 进入条件与本阶段边界 |
|---|---|---|
| 1 | **MySQL：P0-E3** | 持久身份与迁移路线获批、相关 E2 门禁满足、目标和操作获具体授权后，先盘点、再建独立空库与账号、再按另批迁移计划验证 |
| 2 | **MinIO：P1** | P0 相关实证门禁通过且取得 P1 授权；仅图片、原件/派生保护及两个真实测试 Page；不提前开放 P2a 文档业务 |
| 3 | **MongoDB：P3** | P3 外置版本与原生桥接合同获批后，建立专属库、账号与集合；GuidePage 首版 body 必须外置，不以延后建库取消该要求 |
| 4 | **Redis/Celery：按需** | 基线顺序在 MongoDB 之后；由实际缓存或异步任务切片申请，不因依赖已安装而提前启动。若更早阶段确有硬依赖，先修改阶段计划并另获用户批准，不自行插队 |
| 5 | **Elasticsearch：P5** | 正式读取、Outbox、权限回查与单写者合同具备后，申请专属索引、alias 和角色；不为 P0/P1 提前启用 |

以上是本方案涉及基础设施的启用顺序，不跳过路线图的 P2/P4 业务门禁。不得一次性预创建全部服务资源。未启用服务保持关闭、无凭据注入、无启动探活、无任务发现；必要的框架搜索依赖不等于正式 ES 已启用。

备选方案是新站独立服务实例，隔离更强但运维与容量成本更高。若共享实例无法证明 ACL、权限拒绝、容量及备份边界，必须转为独立实例或阻断该阶段，不能退化为“大家约定不用旧资源”。实际实例选择待用户批准。

## 4. 统一隔离、网络与分权合同

### 4.1 可访问与不可访问边界

下表是未来授权后的预期边界，不是当前连通性或权限结果。

| 主体 | 可访问范围 | 明确不可访问范围 |
|---|---|---|
| 局域网普通读者 | 已发布公开页面、明确公开图片及按 P2a 接通的公开附件 | 数据库/Redis/ES、MinIO 控制台、私有原件、草稿/预览/后台；不能因同一局域网而免认证 |
| 后台管理员/编辑/审核员 | 按原生 User/Group/Page/Collection/Workflow 授权访问后台 | 不自动获得建库、桶策略、ACL、队列管理、主机或备份恢复权限 |
| 新站 Web | 当前阶段获批的 SQL 库及受限存储接口，后续按需增加服务 | 旧站资源、服务管理端点、管理员凭据、未启用服务、备份密钥 |
| 新站 worker | 显式任务路由所需服务及指定 namespace | 旧队列、旧任务、跨项目索引、未批准的资源清理与全局管理操作 |
| 迁移/资源初始化执行者 | 工单列明的目标和临时权限，限时启用 | 从一个服务的授权推导另一服务权限、操作旧资源、全局授权或自行扩展目标 |
| 备份/恢复执行者 | 新站专属备份范围；恢复仅到另批批准的隔离目标 | 用旧站备份覆盖新站或反向覆盖旧站、在线原地恢复、将备份路径公开 |

网络采用默认拒绝，只放行明确的运行节点、服务端口和必要运维入口。读者入口与数据/管理平面分离；不因应用需要连接服务而把其端口向整个 LAN 开放。TLS、CA 与证书校验能力未知，需 E3；如需任何传输安全例外，必须单独审批，不默认关闭校验。主机共享下的系统管理员仍有更高访问能力，命名空间不是物理隔离或抵御主机管理员的承诺。

### 4.2 角色与账号

按服务至少区分运行、初始化/迁移、备份/恢复和基础设施管理员；Web 与 worker 按实际职责进一步分开。服务账号不可登录 CMS，CMS 管理员不可由此获得服务管理权。

每个账号限定服务、实例、资源、来源节点、动作、有效期与 owner。运行时不注入管理员或迁移凭据；初始化凭据到期撤销/禁用，后续变更重新授权。若单个实例缺少所需分权能力，标为阻断，不以共享 root、默认用户或全权限 access key 替代。

### 4.3 防误删与未知结果

- 操作前双人核对环境标签、实例指纹、资源精确名、owner 和允许动作；`test` 后缀不是安全证据。
- 变更工单把只读盘点、创建、迁移、运行验收和恢复分开。删除、清空、全局 purge、重启、部署不隐含在任何创建授权内。
- 初始资源非空、旧迁移历史、名称冲突或权限范围不明时停止；不执行 fake、清库、重置历史或覆盖。
- 超时/断连视为结果未知，先按同一操作身份和目标对账，再决定重试；不换资源名盲重放。
- 页面 SQL 删除不触发共享文件或 Mongo 版本物理删除。运行账号必要的 SQL 删除权限不等于授权任意人工删数据；原生删除与历史引用保护仍需应用合同和独立复核。

## 5. MySQL：P0-E3 首要计划

### 5.1 目标与账号最小权限

目标独立数据库为 **`wagtailblog2_next_test`**，不采用旧库改表前缀，不复制旧数据或迁移链。字符集、排序规则、事务引擎、时区和兼容参数经版本盘点及框架兼容审查后确定，不在未知环境直接套用参数。

| 账号候选 | 最小职责与权限范围 | 禁止与限制 |
|---|---|---|
| `wb2_next_test_app` | 仅目标库运行所需 `SELECT/INSERT/UPDATE/DELETE`；后续可按实测收缩到表；来源节点白名单 | 无 DDL、无账号/授权管理、无全局权限、无旧库访问 |
| `wb2_next_test_migrate` | 仅目标库；实际迁移确需的 `CREATE/ALTER/INDEX/DROP/REFERENCES` 与必要 DML，经迁移文件逐项核定 | 不授 `GRANT OPTION`、全局权限、其他库权限；不作为 Web/worker 账号 |
| 初始化管理员 | 另批授权下创建目标库、限定账号和授权；执行后交接 | 凭据不进入应用，不复用旧站运行账号 |
| 备份账号 | 按选定备份工具核定目标库只读及必要附加能力，单独审查 | 不预授全实例读取或锁定权；若工具必须全局权限，应另批或改用隔离方案 |

数据库名含下划线，未来授权时须按实际 MySQL 版本和授权匹配规则处理，验证其只匹配完整目标库，不因通配符解释放大范围。本文不提供可复制的授权语句。

**迁移账号的 `DROP` 是高风险能力。** 数据库级授权可能允许删除该库，不能声称“只能删表、不能删库”。若迁移确需该能力，应采用短时授权、完整脚本审查、备份/恢复检查点和双人执行；不需要时不授予。账号配置本身不能代替防误删流程。

### 5.2 未来操作计划

1. 用户批准具体实例、库名、来源节点、账号分权、只读盘点与后续创建范围；记录版本及旧站占用，不读旧业务内容。
2. 在只读盘点授权下核对实例、目标库名冲突、旧站/其他业务占用、创建能力、网络/容量/备份限制；资源归属不明或目标已存在即停止，不进入创建。
3. 完成持久 User/资源身份、模型和真实迁移源码审查，取得完整相关 E2 证据；缺少自有迁移时先返回另批工程切片，不在 E2 现场生成。
4. 单独取得创建授权后，由初始化管理员创建独立库和限定账号；此步骤不包含迁移。创建后立即复核实际实例、空表/空视图及无 `django_migrations` 历史，非空即停止，不清理。
5. 另批批准具体迁移文件、执行窗口、目标、权限和恢复检查点后才迁移。用迁移账号，不用 app 账号或旧账号。
6. 核对实际表、迁移历史、ContentType/权限、User、Collection 及资源关系；用 app 账号完成获批运行检查，验证 DDL 与跨库访问被拒绝。
7. 原生后台真实创建/登录/禁用、组/页面/Workflow/Collection 权限另记证据，不能只凭表结构宣布验收。撤销临时迁移权限，保留状态与审计。

失败不保证 MySQL DDL 可被应用事务整体回滚；保留实际状态，先查已完成操作，禁止自动反向迁移、删库重建或恢复覆盖。恢复到新隔离目标须另行授权。

## 6. MinIO：P1 公开交付与私有原件分层

**本轮确认：**按“全桶私有、应用受控交付”的建议建设目标 Bucket `wagtailblog2-next-test`，创建专用受限凭据；本轮只完成设计记录，尚未创建 Bucket 或凭据。

### 6.1 桶、对象与公开边界

目标独立桶为 **`wagtailblog2-next-test`**，不复用旧桶。推荐在该桶中划分：

| 前缀候选 | 用途 | 交付与权限 |
|---|---|---|
| `private/originals/` | 私有原件、受保护源文件 | 无匿名访问；仅原件读写角色按需访问；不得直接返回其公开 URL |
| `private/staging/` | 尚未完成上传/分类/绑定的产物 | 无匿名访问；超时/失败保留并对账，不自动清理 |
| `private/derived/` | 草稿、预览或受限派生产物 | 通过受控入口交付；不得进入公开缓存或公开前缀 |
| `public/images/` | 已明确批准公开的图片交付副本 | 普通读者无需逐文件登录/签名；发布分类审核后才写入 |
| `public/documents/` | P2a 才启用的公开附件副本 | P1 不开放、不预填对象；P2a 按公开分类接通 |

公开是资源分类决策，不由 Collection、页面单次引用或对象键推导。私有页面引用已公开资源不会自动使该副本私有；公开页面不能自动解密私有原件。不得把草稿先上传公开前缀、再依赖页面状态隐藏。

**推荐 P1 默认拓扑是全桶私有、由新站受控交付层向普通读者提供公开派生对象；不向 MinIO 直接开放匿名读。**这样可以把公开页面的简单访问与原件/管理平面隔开。若 E3 证明同桶公开前缀具备可靠的源站绕过防护，且用户另行批准匿名读方案，才可选择条件分支：只允许已启用公开前缀的对象读取，不允许桶根匿名策略、匿名列举、私有前缀、历史版本读取、上传、删除或管理。两种拓扑不得混用验收口径；策略须包含对根路径、私有对象、列举和版本入口的负向验收。公开副本已被下载后不能承诺收回；撤销后的源站、缓存和残余窗口须在 P1/P2a 审定。

若目标版本无法可靠按前缀限制公开读取，则保留全桶私有，通过仅暴露公开对象的交付层提供无需读者登录的 URL；或另提双桶方案，待用户批准，不整桶公开。

### 6.2 凭据分权与防覆盖

- 不使用 root、旧站 access key 或整桶管理员凭据运行应用。原件摄取、派生生成、公开副本写入、受限读取、桶管理和备份分别授予最小范围。
- 运行角色无桶策略/ACL/生命周期/版本配置修改权，无整桶删除、对象版本删除、原件物理删除权；公开写入角色也不能写入私有原件区。必要的受控撤销权限单独审定，不给原件删除权。
- 原件与需保留的派生产物采用新资源身份及不可复用对象键；替换必须生成新身份，不覆盖原键。签名、凭据与原件对象键不进入公开日志。
- **仅有随机键、写前 HEAD、禁止 DELETE 或开启版本化，都不能单独证明不可覆盖。** `PutObject` 的范围授权不自动构成“只允许首次创建”。
- E3 必须验证目标版本和客户端支持的原子条件写、重复写拒绝及并发冲突行为，并保证所有上传路径无法绕过。无法直接强制时，可另审只有存储网关持写凭据、由网关强制条件写的方案；不能证明无覆盖路径则阻断 P1 原件写入。
- 版本化是额外恢复保护，是否启用及历史版本配额须先批准；可选对象保留/锁定能力与成本为 UNKNOWN/需 E3，不默认可用或已启用，也不替代应用不可变合同。
- 不配置无人审查的生命周期删除；孤立对象只登记待对账，回收另批授权。

未来验收至少包含：空桶/名称归属、权限实际范围、公开与私有直读、匿名列举拒绝、整桶公开修改拒绝、原件覆盖/删除拒绝、重复与并发上传、SQL 回滚后的对象保留、两类测试 Page 共享及历史引用保护。资源创建成功不等于上传、授权或业务验收通过。

## 7. MongoDB：P3 不可变外置版本

目标独立库候选 **`wagtailblog2_next_test`**，认证用户只服务新站；`authSource`、拓扑、集合名、schema、唯一索引及写确认要求在 P3 审定，不沿用旧站 URI 或账号。

| 角色候选 | 权限合同 |
|---|---|
| 外置版本写入者 `wb2_next_test_versions` | 对获批版本集合仅必要的 `find/insert`；禁止 `update/remove`、删集合/库、索引及用户/角色管理 |
| 正式读取者 `wb2_next_test_reader` | 仅获批集合读取；读取入口仍按 SQL 当前资格和完整版本身份选择，不能读取“最新文档”决定发布 |
| 集合/索引初始化者 | 另批授权创建限定集合、validator、必要唯一索引；与运行凭据分离，用后撤销 |
| 备份/恢复者 | 精确新站范围，工具所需附加权限另核；恢复到另批隔离库，不持在线业务写入凭据 |

不直接授予过宽的 `readWrite`、`dbOwner`、跨库读写或管理员角色来替代不可变合同。角色动作、集合创建副作用及系统集合范围必须按目标版本核实；必要的可变协调信息应另列集合和最小权限，不能放宽版本集合的不可变权限。

版本身份至少绑定环境/owner、field、version、schema/codec 和内容摘要；Manifest 与正式指针由 MySQL 管理。唯一约束与幂等冲突细则须经 P3 审查，本文不创建索引。相同幂等键不得改绑载荷，预写后 SQL 失败保留版本；跨存储补偿路径 Mongo 物理删除为零。

未来 E3 验证：空目标与集合 owner、跨库拒绝、重复身份/不同载荷拒绝、不可变更新与删除拒绝、完整 Manifest/Revision 绑定、正式/预览隔离、超时未知结果和 SQL 失败保留。GuidePage 首版 body 外置合同不变，但不能据此提前连接 MongoDB。

## 8. Redis/Celery：按需隔离

### 8.1 Redis ACL 与 key/channel 合同

推荐按用途划分账号与命名空间；逻辑 DB 号待盘点后决定，不指定“空闲 DB”作为既成事实。

| 用途 | key 前缀候选 | 账号/频道边界 |
|---|---|---|
| 缓存 | `wb2:next:test:cache:` | cache 账号，仅自身键；如需 pub/sub，仅自身频道 |
| 有界协调/锁 | `wb2:next:test:coord:` | 独立职责账号；锁失效不得绕过关键权限/发布条件 |
| Celery broker | `wb2:next:test:broker:` | broker 专用生产/消费角色，按真实传输命令及频道限定 |
| Celery result | `wb2:next:test:result:` | result 专用账号；仅自身结果、分组/回调元数据及必要频道 |

ACL 同时限定命令、键模式和 pub/sub 频道，默认拒绝；不使用默认共享用户或 `+@all`。拒绝全局 `FLUSHALL/FLUSHDB`、`CONFIG`、`ACL`、调试及服务管理操作；普通 `DEL` 等命令按框架确需且仅限自身键，不一概禁用导致 broker 无法消费。具体白名单由目标版本与客户端行为实测确定，不凭文档猜出“完整命令集”。

Redis 逻辑 DB 不是按账号隔离的充分安全边界；不能声称 ACL 天然把一个账号绑定到一个 DB。`SELECT` 是否必须开放及其影响须核对，跨 DB 仍须靠严格 key/channel 限制；无法证明隔离时使用独立实例。禁止通过全局扫描或清空测权限，拒绝测试只用经批准的合成目标与可审计方式，不读取旧键内容。

缓存与 broker/result 的容量、TTL、持久化及淘汰需求不同；不能为了缓存命中率修改共享实例全局淘汰配置。若共享内存压力、淘汰、连接上限或持久化策略会危及旧站/任务可靠性，拆分实例或停止。

### 8.2 Celery 队列、路由与结果

- 队列候选：`wb2.next.test.default`，按需增加 `wb2.next.test.media`、`wb2.next.test.outbox`；未批准任务不提前建队列。若采用非 Redis broker，vhost/exchange/binding 也须独立审定，不能套用 Redis 方案。
- 任务名采用 `wagtailblog2.*` 候选空间；显式列出任务、路由与队列白名单，不使用旧任务自动发现，不依赖共享默认 `celery` 队列。未知路由应失败，不悄悄创建队列。
- worker 只消费批准的新站队列，独立进程身份、节点名、配置和凭据；不消费旧站队列，不默认启用远程控制/广播或事件订阅。确有需要时频道也纳入专属 ACL。
- broker 传输层前缀与 result backend 前缀分别配置；Redis/Kombu 的 `global_keyprefix` 等选项是否适用于选定版本须 E3 验证，不能以写了配置项代替隔离证据。
- broker 命名空间须覆盖主队列、优先级变体、binding、unacked/QoS、fanout/control 等实际生成的键/频道；result 须覆盖任务、group/chord 等实际元数据。只改 queue 名或普通 Django cache 前缀都不足够。
- beat 若启用，调度状态文件/键与运行身份独立，防止多个调度者重复投递；不继承旧 schedule。
- 使用明确允许的序列化格式，拒绝任意代码对象反序列化；结果不存完整正文、凭据或预览授权。结果 TTL/容量按任务申请审定。
- SQL Outbox 是持久事实，broker/result 不决定发布成功；按事件身份/代次幂等处理重复和乱序。断线/超时先查持久操作状态，不用清队列“修复”，也不把 result 丢失当业务回滚。

未来验收按真实客户端采集自身生成的键/频道清单及拒绝计数，验证跨前缀拒绝、错误路由失败、worker 只消费本队列、结果命名空间与过期、重启/重复/超时/积压恢复。不得向旧队列投递测试消息或运行全局 purge。

## 9. Elasticsearch：P5 专属投影与单写者

| 项目 | 候选合同 |
|---|---|
| index prefix | `wagtailblog2-next-test-`，仅覆盖新站获批物理索引 |
| 物理索引 | 例如 `wagtailblog2-next-test-content-v001`；新代次先建新索引，不原地覆盖旧/当前索引 |
| 读 alias | `wagtailblog2-next-test-content-read` |
| 写 alias | `wagtailblog2-next-test-content-write`，只指向明确的新站写目标 |
| 读角色 | 仅批准读 alias 的搜索读取及框架确需元信息；不授旧索引、集群管理或任意物理索引读取 |
| 写角色 | 单一 Outbox 投影写者，仅写 alias 所需索引/更新/删除投影动作；业务删除投影不等于删除源数据 |
| 建索引/切 alias 角色 | 限新站前缀与指定 alias 的建索引、mapping、必要 alias 管理；短时启用，不交给 Web 或普通 worker |

具体权限名称与 alias/物理索引权限组合必须按真实版本核验，不能将 alias 当作独立强安全边界。索引角色不得使用全局 `*`、旧站前缀、跨项目重建权限或集群 `all`。新站模板/生命周期/快照策略也须专属名称与范围，不修改共享默认模板；共享集群设置变化另批授权。

原生搜索自动更新与 Outbox 必须明确各自物理索引所有权，禁止竞争同一正式物理索引/alias。只选一条正式写入链路；框架后台必要搜索另定边界，不因禁用冲突写者而破坏原生功能。

重建计划：基于 SQL 当前正式身份与对应外置快照写新代次，追平 Outbox、核对权限/版本/数量与延迟后，另批切换 alias；保留原代次至观察期结束，删除旧代次另行批准。重建不得读取旧站索引作为新站业务权威。

搜索返回前批量回查 SQL 当前资格和正式代次；标题、摘要、高亮、建议词及统计也不能泄漏草稿/撤销内容。ES 丢失可从权威数据重建，但重建正确性与耗时须 E3，不能以“可重建”跳过权限和恢复验收。

## 10. 凭据与独立备份管理

### 10.1 凭据

每个环境、服务和角色独立生成与保管秘密；本文只保留角色/资源候选名，不生成或保存密码，不复制旧 `.env`。秘密通过批准的秘密存储或受保护的运行配置注入，不提交 Git，不出现在命令行参数、日志、截图、异常和报告中。示例配置只能出现无效占位符，缺少目标或关键参数时明确失败，不回退到旧站。

交接记录保留凭据引用编号、owner、权限范围、来源节点、轮换/失效日期和吊销流程，不保留秘密值。轮换先验证新身份，再撤销旧身份；不得因轮换修改旧站凭据。备份密钥与业务密钥分管，主机管理员残余权限明确披露。

### 10.2 备份与恢复

U36 已确认简单备份目标：每日备份、约 30 天保留、最多约 24 小时数据损失；这是目标，不是当前能力证明。RTO、备份时间窗、容量、加密/离机位置和工具仍为 **UNKNOWN/需 E3**。

- 使用新站专属备份目录/桶/前缀、账号、保留策略及加密密钥，不能混入旧站轮转清理规则；备份不可位于公开媒体前缀。
- 按阶段备份已启用资源。P0 仅 SQL 与必要配置；P1 加 MinIO；P3 加 Mongo。备份覆盖正式状态、Revision/Manifest、owner/删除屏障、引用证据、Outbox、水位及二进制身份；不为图片局部验证强行快照无关服务。
- 跨存储不能只做几个独立 dump 就宣称一致。每次备份记录同一恢复集编号、SQL 检查点及其所引用 Mongo 版本/MinIO 对象版本闭包，确保权威引用存在，再完成校验和及可恢复性验证。
- Redis cache/result 不作为业务恢复权威；broker 是否持久化与如何从 Outbox 重放单独审定。ES 快照可作为加速手段，不代替 SQL/Mongo/MinIO 权威备份。
- 恢复先到另批批准的新隔离目标；先恢复所需不可变文件/版本与 SQL 检查点并验证引用闭包，冻结 worker/公开入口，随后对账 Outbox/代次、重建派生投影，再经权限和用户态验证后决定启用。不得在引用未齐全时对外服务。
- 备份成功、校验通过、真实恢复通过分别记账；无恢复演练不得宣称具备 U36 保障。恢复、删旧备份或清理对象均另需操作授权，不原地覆盖新旧在线库。

## 11. E2/E3 关系、操作闸门与停止条件

### 11.1 证据分层

| 层级 | 能证明 | 不能证明 |
|---|---|---|
| E1 静态设计 | 本文、名称/角色/阶段与风险合同可审阅，引用和格式可本地检查 | 任何真实资源存在、权限、连通性、创建或迁移结果 |
| E2 无外部 IO | 项目/settings 导入前安装并验证 DB（含 SQLite）、网络、Storage、任务和子进程守卫；负向探针及违规计数有效后，受守卫检查获批模型/入口及已有迁移图状态 | 实际建库、SQL/数据迁移、账号权限、文件上传、真实原生后台或服务隔离 |
| E3 真实隔离验证 | 另获具体目标、来源节点和操作授权后的只读盘点、创建/迁移及真实服务/后台测试，按范围分项举证 | 自动授权生产、旧站访问、其他服务或下一阶段，也不能代替持久身份批准 |

普通 `manage.py check`、SQLite、LocMemCache 或“没有观察到连接”不是完整 E2。异常被业务捕获也不能忽略违规计数；Mock 必须披露，不能折算真实服务证据。12 号方案的编写与审阅不运行应用导入或 E3；当前 E2 守卫测试的有限结果另见 11 N4，仍不构成完整 P0 E2。

### 11.2 未来工单的严格闸门

1. **设计批准**：确认资源/账号/网络/分权与所涉持久身份，列明允许动作及禁止动作。
2. **只读盘点批准**：限定具体服务和来源，核对版本、旧站占用、资源归属与创建能力；未知项不擅自补探。
3. **E2/独立复核门禁**：在任何真实创建或迁移前，完成导入前无 IO 守卫、获批模型/迁移图验证和高风险独立 Reviewer 复核；E2 不连接目标服务。
4. **创建批准**：按阶段精确创建本次资源，登记创建后空目标与权限证据；没有迁移权限则止于此。
5. **迁移/变更批准**：持久身份和实际迁移源码审定后，限具体文件、目标与窗口执行；其他服务按各阶段初始化工单处理。
6. **真实验收批准与执行**：运行账号正向、合成越界负向、故障恢复和必要原生后台/浏览器/用户态分别记录；由 Terra 整合、用户/授权人验收。

**立即停止条件：**

- 未批准的主机、实例、数据库、桶、前缀、队列、alias、账号或操作；连接默认值/环境来源不明。
- 目标非空、存在旧历史或资源归属不清；实际权限可访问旧站资源、全局管理或未批准 namespace。
- 必须使用 root、整桶公开、共享默认用户、全局清理、无条件原件覆盖、放开公共数据端口才能继续。
- E2 守卫失效/越界、身份或迁移图缺项/冲突、真实版本不兼容、无法证明来源节点与网络限制。
- 磁盘/内存/分片/配额或备份限制会影响旧站；无可用恢复检查点而拟执行不可逆高风险操作。
- 发生未知写结果、错误路由、跨库/跨桶/跨队列/跨索引写入、草稿/私有内容泄漏或不可变版本可修改。
- 无法实现原生生命周期、正式快照一致性、权限拒绝、单写者或 Mongo 零物理删除合同。

停止后冻结本批后续动作、保存脱敏证据和持久操作身份，通知 Terra/用户。不得自动删资源、清队列、反向迁移、改全局设置或重启“自愈”。恢复与补偿方案需独立授权。
