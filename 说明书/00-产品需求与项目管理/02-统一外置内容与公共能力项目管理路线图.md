## 2. 关键合同与依赖

P0 在首次迁移前固定 User、资源模型和迁移依赖图。仓库选项 A、Conda `wagtailblog-test` 独占使用、迁移路线 B、`resources`/`site_home` 基础身份和编辑/发布分权基线已按 04 U24/U25/U37～U39 确认；`site_identity.User` 已完成 P0-DEV-01，资源与首页 App 尚未实现。测试与未来正式站使用同一自有迁移历史，测试夹具另行标识。不允许 fake、清库或更改旧历史来满足图。资源模型无法原生兼容时先报告阻断项。

后续 Python 测试使用用户分配的 `wagtailblog-test` 环境；U39 已确认直接依赖按 `pyproject.toml` 的稳定版精确基线管理，兼容性例外和更新证据单独记录。依赖基线不等于项目装载或 SQL/Mongo/MinIO/ES/Redis/Celery 目标已验证，不把环境独占等同所有外部服务可用或可写；新仓库 Windows 路径为 `F:\openclaw\workspace\wagtail\wagtailblog2-next`，WSL 映射仅用于本地验证。

P0 分 E1/E2/E3 三层证据，具体合同只在 09 §10.2 维护。E1 是可审阅静态设计；E2 是在导入前布置并验证无 IO 守卫后的装载/图/模型状态验证，不要求数据库目标授权，也不允许实际数据库/网络/Storage/任务 IO；E3 是具体隔离目标和操作授权、空目标预检之后的真实迁移及必要后台/服务验收。U27～U36 是产品行为确认，不等于模块实现或 E3 授权。当前 E2 守卫切片正在实施，完整身份/媒体模型和迁移图合同仍须在相应持久身份获确认后验证；E1/E2 不能自动准入 P1，也不能证明第三方数据迁移可以执行。

Registry/Card/Access/Selection/Discovery/ExternalField 的最小输入、输出及错误语义草案已在 09 §14.2 补齐，涵盖 ReadContext、SnapshotRef、当前权限与一致正式快照、三道选择校验和有界批量读取；均非 Wagtail 内置 API，尚未实现。后台角色及“仅本人草稿/同栏目按组限制类型”按 §14.1.1 调查原生边界。P1 仅实现图片所需子集，不强行实现所有 Provider。评论与互动是实时业务记录，人员/相关文章/编排是可恢复的编辑关系；插件三级风险及历史兼容见 §14.3，资源分类/引用/直接下载矩阵见 §5.5。

P3 是高风险核心门禁。发现某原生路径无法保留时，应补足接入验证与协调设计；不得增加第二个发布按钮、独立 Mongo 审批或“只支持手工发布”的永久绕过。

P4b 明确引用的所有者：Home/父页面 Revision、正文 Mongo 版本、独立 Snippet Revision。关系变动随所属对象发布；目标资格变化立即影响读取，不等待父页重发。Page 目标建议 SET_NULL 加失效占位，固定集合版本需 pin/保留策略，均须真实删除和历史重放验证；当前权限不能由历史快照恢复。首页六场景及移动端/键盘/焦点/暂停/减少动画/失败回退按 09 §15.5 验收。

P5 明确原生搜索自动索引和 Outbox 各自负责的物理索引、别名与禁用边界；旧链路并存不等于已证明同索引冲突。Archive 聚合用可重建增量投影，重建/分页不能无界扫描。

## 3. 各批次证据与管理

每批记录授权范围、变更文件、测试环境/命令/结果、未验证项和回退方式。静态、Mock、真实数据库、真实外部服务、离线浏览器和登录态证据分开。适用代码门禁包括 diff 检查、Django check、CSS token 检查及定向业务测试；文档/代理配置调整不伪造应用检查。

Terra 负责主控调度、授权边界、文档同步、整合与最终验收；Sol 负责架构合同和技术提案；Gemini 负责批准范围内工程实现；跨存储核心、完整阶段或用户明确要求时，另派独立 Reviewer 只读复核。小任务可按风险由 Terra 决定是否派 Reviewer，不强制跑全角色流水线。任务按可恢复单元拆分，不以固定 5～10 分钟作为唯一完成标准。模型和 effort 只用已验证组合，产品阶段不绑定模型名。

本轮无本地提交授权，不提交。以后提交须有当轮授权和门禁证据；合并、推送、生产及破坏性操作仍需对应明确授权。保留所有无关工作树变更。

## 4. 容量与恢复

P1 记录上传/rendition 和引用成本；P3 记录保存/发布延迟、Revision/Manifest/版本增长；P5 测量冷热查询、增量归档与索引延迟；P8 在明确硬件、数据量、并发、采样窗口后逐级放大。覆盖 Page Tree 路径/移动、Revision 历史、Mongo 版本量、ES 分片和聚合、队列积压与全量重建。

每级均记录 P95/P99、错误率、查询数、锁等待、存储增长和恢复时间。达到上一档不能推定能支持一亿篇；大规模树结构、保留期和索引分区方案依据实测另行评审。

恢复以 SQL 页面/绑定/正式状态及持久删除屏障为主线，核验 09 §5.3 的完整引用保护闭包和 Mongo/对象版本，最后重建投影/缓存；P8 验证固定集合版本、Alias、未知操作、预写/导入产物及待投递事件不会被误判可回收。RPO/RTO 由用户和实际演练确定；旧“10 秒恢复”不适用新站。
