## 1. 第一批要交付什么

新站从第一天使用真正独立的 `resources.Image` 与 `resources.Rendition`，接入 Wagtail 原生后台、chooser 和 MinIO。两种真实测试 Page 可以选择同一图片作封面和正文插图，分别保存说明、生成派生图并显示。

本批的公共图片服务不能依赖 `blog.BlogImage` 或 `resources.adapters.blog_resource`。只增加 DTO、重命名函数或给旧 Blog 模型包一层服务，不算本批完成。

第一批先证明公共图片基础，不同时建设完整 Mongo 生命周期、正式 BlogPage/GuidePage、文档、导入和搜索。

## 2. 为什么要有 P0

当前站点仍以 Blog 模型作为全局图片与文档模型，旧应用和迁移也互相依赖。仅修改一个 setting 后执行旧迁移链，可能仍然创建 Blog 资源或形成冲突。

因此先准备新站启动配置、最小应用白名单和迁移图设计。用户已选择完全独立的新站 Git 仓库；旧仓库和旧配置/迁移只作为只读历史参考，不作为新站建库约束。09 §10.1 的迁移 B 仍为技术推荐，尚待逐项审定；§10.2 的根包 `wagtailblog2`、身份 `site_identity`、公共资源 `resources`、首页 `site_home`、测试夹具 `resource_fixtures` 继续作为新仓库候选。第三方保留原生 label/迁移，不复制整个旧项目，也不同时装载新旧 resources 包。迁移 A 的同 label 新初始模块仅有条件备用，与已确认的仓库选项 A 不同；`MIGRATION_MODULES` 不能隔离模型、ready/hooks/信号。候选 AppConfig/包/label 及资源依赖均未创建或验证；选定后新站生产模型在测试/未来正式各环境使用同一历史，不能临时切图。

P0 先形成启动与建模的可审阅合同，不提前实现所有应用。首次迁移合同同时固定公共图片/文档模型配置及最小 `resources.Image`、`resources.Rendition`、`resources.Document`，标出 Rendition 外键、User、Wagtail/第三方 swappable 与显式依赖和潜在环；09 §10.2 已列源码事实和自有依赖候选，不能当作已生成/加载的图。最小 AbstractUser 方向已获用户确认（04 U26），保留原生认证/组/权限，不加会员、支付或业务资料字段；身份包/label、AUTH_USER_MODEL 具体值、所属初始迁移依赖和 Wagtail/第三方兼容仍待审定及验证。公共 Person 与 User 可选关联不自动授权，初始身份迁移不反依赖资源或 Page。图片业务在 P1 完善；Document 的上传、下载、业务块和管理功能在 P2a 验收，P0/P1 不开放文档业务入口。模型声明不是业务交付。

证据分 E1 静态设计、E2 受守卫无 IO 装载/图验证、E3 真实隔离空库/后台/服务验收，详细合同归 09 §10.2。本文件原始方案属于 E1；N4 已另行登记受守卫 Mock 测试的有限证据，但完整自定义模型/迁移图 E2 仍未完成。后续配置/原型实施另获授权后才能创建模型/迁移及守卫、执行 E2，守卫须在任何项目导入前阻断数据库、网络、Storage 和任务 IO。合格的无 IO E2 不需数据库目标授权，但不能证明 SQL 或第三方数据迁移可执行。E3 的目标预检、迁移及测试分别受具体目标/操作授权约束，不自动准入 P1。

真实 IO 前须明确测试主机、库、桶/前缀和队列并取得对应读写授权。12 号基础设施方案提出 P1 候选 MinIO Bucket `wagtailblog2-next-test`，但该名称、主机、权限和空状态仍待 E3 盘点，不是本轮许可；完整资源/账号/网络隔离合同以 12 号方案为准。旧说明中的远端地址和资源名仅为历史候选，不是本轮许可。主机地址不能证明隔离；本轮不连接任何数据库或对象存储，P1 也不需要 MongoDB 或 Elasticsearch。首次迁移前完成 U26 对应的身份标识审定、迁移依赖与兼容验证，以及 Registry/Access/编排的最小数据与权限合同；Provider 草案已在 09 §14.2 补齐，不等于本批实现全部能力。

Python 测试环境按用户确认独占使用 `conda activate wagtailblog-test`；本次已在独立新仓库 `F:\openclaw\workspace\wagtail\wagtailblog2-next` 建立最小骨架并完成无外部 IO 静态核验。Conda 分配不代替服务目标核验、具体 IO 授权或 P1 验收。

不假定目标库已经创建或仍为空。初始迁移前检查现有表、迁移历史与数据；已有内容时保留并停止初始化，再确定经授权的空白目标，不清库、不覆盖、不 fake。

## 3. 实体与页面引用

### 3.1 公共实体

| 对象 | 设计 | 关键约束 |
|---|---|---|
| Image | 继承当前 Wagtail 原生图片抽象模型 | 公共 app 所有；原件对象键不可覆盖 |
| Rendition | 继承当前 Wagtail 原生派生图抽象模型，关联公共 Image | 保留图片、规格和焦点键的唯一性规则 |
| 图片块 | 放在 resources 的公共块模块 | 引用公共模型；alt、图注、装饰性标记属于使用位置 |
| 图片引用记录 | 关联 Image、页面/Revision 或导入身份、字段位置 | 覆盖历史与共享引用；不能只统计当前 live 页面 |

不创建万能资源父表，不在图片模型上保存 BlogPage 外键，不把页面标题或页面业务状态写进图片实体。

### 3.2 页面关系

```text
resources.Image
  ├─ 测试页面甲.cover_image
  ├─ 测试页面甲.body 中的图片块
  ├─ 测试页面乙.cover_image
  ├─ 测试页面乙.body 中的图片块
  └─ resources.Rendition
```

封面使用保护型外键。正文图片和图集分别保存各自的 alt、说明及顺序，不能把某篇文章的图注写成全局图片属性。

初期引用随原生 SQL StreamField 和 Revision 验证；P3 再将同一引用协议接入外置 Manifest。该测试存储仅属于测试 Page，不代表正式 BlogPage.body 选择继续留在 SQL。

## 4. 两种测试 Page 的明确范围

候选测试包为 `wagtailblog2.tests.resource_fixtures`，AppConfig 为该包下 `apps.ResourceFixturesConfig`，label 为 `resource_fixtures`。以后建立仅在测试站配置启用的独立测试应用，包含 `ResourceArticleTestPage`、`ResourceGuideTestPage` 两种 Wagtail Page 模型。每种有标题、封面、最小正文和预览模板；本批尚未创建。

它们必须是真实模型、真实数据库记录和后台可编辑页面，不能只用 Python 假对象调用服务。测试应用不能放入公共资源的业务模型中，也不能进入最终站点的生产应用清单。

这一步验证“公共图片与页面类型无关”。正式 BlogPage 和 GuidePage 的业务字段、Mongo 正文、列表、发布和前端详情在 P4 再验收。第一批报告不得写成“指南系统已完成”。

待正式双页面验收通过，测试应用仍可保留作回归夹具。测试夹具 App/迁移额外标识且不进入正式清单；公共资源及其他自有生产模型始终沿用测试/未来正式同一迁移历史，不为测试另建一套生产模型图。

## 6. 上传、访问和删除边界

U28 已确认首版局域网公开交付保持简单：已发布页面中的公开图片正常加载，公开附件可直接下载，普通读者不需要逐文件登录或临时下载凭据。后台上传管理、草稿、未发布内容、私有资源、原件保护和共享引用保护仍必须成立；P1/P2a 只验证必要保护，不建设复杂逐用户逐文件权限系统。

- 上传校验大小、类型与可解码性，原件使用独立对象键；只接受有权限的上传请求。
- 建议采用私有桶与由新站负责的受控公开交付；实现细节可使用内部签名或等效机制，但不改变普通读者无需登录的产品行为。仍须证明原生后台预览、chooser、rendition、缓存和私有资源保护兼容，不能仅改桶 ACL 就声称完成前台授权。
- 前台读取校验当前页面引用与访问范围；URL 中仅有 image_id 不能构成授权。
- 公开页面可缓存图片派生结果；私有预览不得复用公共页面缓存。
- 原图查看与下载按资源公开/私有分类交付；公开附件不强制逐文件登录，私有原件和未发布对象不能因知道 URL 自动公开。
- 第一批禁用资源的单个/批量物理删除和文件原地替换；仅隐藏按钮不足，直接请求、服务层及应用级删除入口也须受保护。数据库管理员的破坏性操作不在应用承诺范围内。
- 删除测试页面不删除 Image；共享或历史引用不得因为页面被删除而失效。
- 上传或派生失败记录可诊断的产物状态，保留待对账对象；本批不自动扫桶清理。

### 6.1 P1 图片授权子矩阵

全媒体合同以 09 §5.5 为准，本节只落实图片，不提前交文档/视频。资源安全分类、页面引用与当前请求上下文分别判断，页面不能直接修改 MinIO 全局策略。

| 场景 | P1 必须证明 |
|---|---|
| 公开页引用可公开图片/派生图 | 正常显示且仅公开交付结果可共享缓存；受限原件不会因 Page 公开自动变公开 |
| 私有页复用同一公开图 | 图片本身仍可公开，私有 Page 标题/配置/引用及私有派生不泄露；不承诺已公开文件重新保密 |
| 无上下文直连受限原件/派生图 | 服务端拒绝；image_id、可猜对象键、规格签名均不单独构成许可，绕过路由无效 |
| 编辑预览尚未发布引用 | 验编辑/预览资格及资源使用资格，允许合法预览但不要求具有资源管理权；短时凭证和私有缓存隔离 |
| 撤销/转私有/移动改变祖先限制 | 当前交付立即复核；旧签名、浏览器/CDN 缓存的残余可用窗口须预先约定并测量，不能承诺收回已下载副本 |
| 删除单页/恢复历史 | 其他合法引用仍可用；旧文件按保留合同受保护，历史恢复不恢复过去公开许可 |

Collection 管理范围与前台授权分别验收；私有桶、Storage URL、原生 chooser 缩略图和 Rendition 交付需要真实 MinIO/浏览器组合验证。签名寿命、缓存和撤销窗口在 P1 实施前确认；权限未知拒绝受限交付。本批保留原件/历史，不实现自动物理回收。

ReferenceIndex 可以辅助后台引用展示，但外置正文、Markdown 和历史引用将在后续批次补齐协议。第一批不能宣传自动安全回收。
