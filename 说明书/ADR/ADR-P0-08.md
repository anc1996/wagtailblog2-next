# ADR-P0-08：公共能力协议、原生编辑权限与基础设施权威边界

- 日期：2026-10-31
- 状态：已确认需求与 U38 基础权限合同及 `resources/site_home` 身份的合同化提案；方法名/数据结构为项目建议，非 Wagtail 内置 API，尚未实现。
- 证据级别：E1；无服务、后台动作、发布/删除或跨存储测试结果。
- 用户批准：产品选择、简化公开交付原则、resources/site_home 基础身份和编辑/发布分权基线已确认；未覆盖的技术细化仍待验证。

## 来源、用户已确认与纠偏

依据旧参考仓库 `说明书/00-产品需求与项目管理/` 的 00、01、02、04 U02～U10/U12/U18～U23/U26、08、09 §5/§7/§8/§14/§15、10 §11～14。公共能力不依赖具体 Blog/Guide，Wagtail 原生 Page Tree/Revision/Workflow/权限是生命周期权威；不开发第二套发布系统、会员支付或在线插件市场。

本轮承接 U27～U36、U38；身份 App label、`AUTH_USER_MODEL`、resources/site_home 基础身份、迁移路线 B 及编辑/发布分权基线已获批准。E2 证明与批准分开，授权及验收责任按 ADR-P0-01。

**F16 修正：GuidePage 首版 body 必须外置 MongoDB，按 U04 和本次明确要求执行；旧 01 的“可外置”不再是有效选择。**Blog body/intro 分字段外置；旧 09 的 body 必填、intro 可显式空建议须与 U27～U36 已确认选择核对，仅未覆盖的字段/空值细则仍待审定，不与外置方向混淆。

## 方案建议：模块职责与依赖方向

| 模块 | 拥有 | 不得拥有/依赖 |
|---|---|---|
| BlogPage / GuidePage | 各自业务字段、允许的块、原生面板、模板及具体子关系/注册装配 | 不各造搜索、人员、媒体或发布权威；首版外置字段要求不能改为选配 |
| external_content | 声明字段的 codec/schema、不可变版本、完整 Manifest/Revision 桥、正式读取伴随指针及生命周期协调 | 不成为第二发布按钮；非外置 Page 不制造虚假 Manifest |
| people | 公共展示身份与人员角色；编辑关系随所属原生快照 | 不以 Person 关联/署名授予认证、编辑、审核或阅读权 |
| resources | 公共资源元数据、二进制摄取/处理/交付、引用证据 | 不把整套 Markdown/正文导入编排塞入资源服务；不归某种 Page 所有 |
| 公共搜索/发现 | 正式投影/Outbox 消费、批量资格回查、跨类型发现 | 不读最新草稿，不决定发布，不竞争同一物理索引写入权 |
| content 公共协议 | Registry/Access/Selection/Card 的类型化契约 | 不导入具体 Blog/Guide、不要求每协议建 App |

装配层注册具体类、具体 Page 的 ParentalKey/Orderable 合法；依赖反转不是万能 JSON 容器或消除所有具体关系。`resources` 与 `site_home` 的持久身份已按 U38 固定；其他逻辑模块的最终 Django App label 仍未在本 ADR 定案。

## 最小输入/输出合同建议

`ReadContext`：site、locale、主体/已验证凭证、purpose（卡片/正文/选择/资源/发现）、mode（正式/受限正式/授权预览）。不把凭证写入日志或共享缓存键。

`SnapshotRef`：Page/稳定 owner、原生 Revision、完整内容标记、可选 Manifest/正式 generation。非外置页面 Manifest 可空；正式接口不接受调用方任意指定 Revision 替换正式快照。预览须核验实际对象及 Revision/内容标记/Manifest 组合和当前资格。

| 协议/候选操作 | 输入 → 输出 | 核心断言 |
|---|---|---|
| Registry / resolve | 稳定 type_key、模型引用、协议版本、能力枚举、Provider 声明 → 不可变注册描述 | 启动拒绝重复键、无效模型、缺依赖及不兼容能力组合；注册声明不是实现证据 |
| Access / evaluate_batch | 身份列表、ReadContext、预期快照 → 逐项决定及已核对快照 | 当前发布/祖先限制/site/locale/原生访问规则；权限未知拒绝，不能只看 live 或 Collection |
| Card / load_batch | 已核对快照与上下文 → PageCard 或明确失败 | 正式标题/摘要/日期/URL/type/site/locale/受控封面；不回退草稿，不泄漏私有对象键/未经授权 Storage URL |
| Selection / candidates、validate_batch | 场景、所有者/目标、编辑上下文与顺序 → 有界候选/校验结果 | 校验能力、站点、语言、对象资格，拒绝自身/重复；允许编辑引用草稿不等于前台可见 |

Access 与内容加载必须使用同一快照，不能以 R1 资格加载 R2。代次/访问范围改变则有界复核；取不到一致状态明确失败。历史恢复不恢复过去访问许可。缓存隔离 site/locale/正式版本/访问范围；预览不进入公开共享缓存。

Selection 有 **chooser 候选、POST/保存、前台读取** 三道独立检查；父 Page/版本化 Snippet 的原生事务和 Revision 保存顺序及引用，Provider 不自造发布状态。目标删除、失效占位、集合跟随或固定版本按已确认产品选择落实；未覆盖的技术细则仍需 P4 审定和重放验证。

错误区分 NOT_FOUND/UNREGISTERED/UNSUPPORTED（公开结果合并，防枚举）、DENIED、UNKNOWN_ACCESS（拒绝）、UNAVAILABLE/INCONSISTENT_SNAPSHOT（关键正文/权限失败）、INVALID_SELECTION/VERSION_CONFLICT（可修复保存错误，避免部分覆盖）。可选推荐可按约降级，不能退到草稿或旧授权。批量/候选数/页长/外置读取/超时/重试均有预算；具体数值需测量后审定，避免 N+1 和无界补取。

## Wagtail 原生编辑权限边界

U38 的权限基线为：编辑在授权栏目/对象范围内可修改任意草稿，不限本人创建；编辑与发布权限分离，编辑不能直接发布，审核员按 Workflow、Group、Page Permission 和 Collection 合同负责发布。具体原生入口覆盖、批量操作和直连拒绝仍需 E2/E3 验证。

角色使用原生 Group、树范围 Page Permission、Workflow 与 Collection，不另建 CMS 角色权威。下表是建议配置/测试场景，不代表原生默认已满足。

| 场景 | 允许与独立限制 |
|---|---|
| 栏目负责人/作者/编辑 | 指定树根 add/change，publish 独立授予；Blog/Guide 父子类型规则与组权限分别核对 |
| 仅本人草稿投稿 | add+owner 不自动等于仅本人草稿；测试 change、已发布/退回、owner 变更与任务授权等分支，缺口走受支持对象检查 |
| 审核员 | 指定 Workflow/任务组、对象可达性与编辑/发布许可分别配置；署名角色不授审核权 |
| 删除/移动 | 原生 can_delete 由 add/change/publish/owner/live 后代等组合；非叶涉及 bulk_delete。移动同时核对源资格、目标 add/类型和新祖先限制 |
| 复制/别名/解除别名/排程 | 按实际动作与子树、目标位置、执行时政策验证；不能从 can_publish 单项推断全部检查已完成 |
| 资源管理员/后台只读 | Collection 操作不授 Page 编辑或文件公开许可；菜单隐藏不是直连 URL/POST/API/批量/chooser 防护 |

读者 Access、后台编辑权限、资源管理与下载权限分别判断。原生允许子类型不是同一父栏目内按组分配类型的白名单；按已确认产品选择落实，仅未覆盖的细分和“只读指定对象”细则仍待审定，原生能力须验证，不根据角色名称伪造能力。

### 局域网公开资源的首版交付

已发布且明确公开的内容及其公开图片/附件无需普通读者登录；复杂逐文件授权不是首版产品要求，不为公开读取强制登录、逐文件签名或完整授权引擎。草稿、未发布内容、私有资源和后台仍受保护，局域网部署不能成为开放全部媒体目录/桶或绕过原生权限的理由。公开分类不由 Collection 或单条页面引用自动推导；受限直读、预览凭证和公开共享缓存仍须隔离。

具体分类、路由/桶及受限交付实现按 [ADR-P0-04](ADR-P0-04.md) 另行审定验证；该简化不改变共享资源/历史引用保护、Wagtail 生命周期权威或 P1/P2a 范围，也不承诺收回已下载公开副本。

## 存储权威、提交与补偿合同

| 存储/层 | 权威范围 | 失败或补偿边界 |
|---|---|---|
| MySQL + Wagtail | 原生状态/关系/Revision、Manifest 绑定、正式伴随指针、稳定 owner/删除屏障及 Outbox | SQL atomic 只保护本事务；正式状态/指针/generation/Outbox 同提交 |
| MongoDB | 声明外置字段不可变版本，包含 owner/field/version/schema/codec/摘要 | 预写后 SQL 回滚保留未绑定版本待对账；**跨存储异常路径物理删除为零**，不按“最新文档”发布 |
| MinIO | 不可覆盖的原件/派生二进制对象 | 超时不证明未写入；保留产物按身份对账；不连带删共享/历史文件 |
| Redis/Celery | 缓存、任务与有界协调 | 不决定发布/授权；关键锁不可用或权限不明时拒绝关键操作；可选统计按合同降级 |
| Elasticsearch | 可重建正式搜索投影 | 每个正式物理索引/alias 唯一写入权威；不与原生 AUTO_UPDATE 竞争，不以索引恢复发布资格 |

保存：预留可查询操作身份/载荷指纹，预写不可变 Mongo；SQL 保存元数据、完整 Manifest、资源引用、Revision 和绑定。未变字段可复用同 owner/field 版本，空值与缺字段不同。不能因为只改标题就缺失完整外置绑定。

发布：在受支持原生生命周期协调中复核选定完整快照及当前资格，同 SQL 事务更新原生正式状态/伴随指针/generation 并写 Outbox。建议锁序 Page → 发布/操作状态 → 关联写入，批量按 Page ID；首次树插入和操作身份协调另验，不能锁不存在的 Page。Mongo 网络预检有预算，锁内复核不变身份，不持锁做任意外部通知。

Revision ID 不单独表示不可变内容：旧源码审计发现自动保存可覆盖同 ID。绑定须包含覆盖 SQL 序列化、编辑关系及 Manifest 的完整内容标记；审核/排程冻结实际获审快照，ID 相同内容变化仍拒绝挪用资格。如何安全持久化标记是 P3 阻断项，不声称原生 TaskState 已提供该能力。

原生 Alias 无自身 Revision，需独立源快照绑定及源/Alias 当前资格检查；复制/解除别名分配新 owner/完整绑定，keep_live 也须经过已验证原生发布协调。移动影响整个子树访问/投影。原生 SQL 删除同事务保留独立 owner 删除屏障和事件，不假定被级联删除的 Revision 可恢复，也不另造仅软删除生命周期。

Outbox 建议至少带 event_id、page/owner、type_key、正式 revision/可空 manifest、generation、schema_version、kind；删除事件不依赖 Page 行存活。on_commit 只唤醒，持久扫描可恢复；消费者按当前权威身份/代次幂等处理重复、乱序、撤销/tombstone、重建及重启，不让迟到事件或同数值 ID/URL 重建复活旧内容。

超时/断连属于可能已提交：先按持久化操作身份查询/对账；同幂等键不可改绑载荷，不换键盲重放。搜索返回前批量核对 SQL 当前资格及正式版本；过期标题/摘要/高亮/数量/建议词/Feed 同受约束，不只过滤正文。详情正式快照缺失或权限未知明确失败。

## 独立基础设施、插件与实施切片

具体资源隔离和启动合同见 [ADR-P0-06](ADR-P0-06.md)；独立仓库/命名空间不是服务存在、为空或获准连接的证据。插件声明身份、版本、依赖、权限与数据所有权；仅经验证核心参与者进入 SQL 事务，可选插件消费已提交事件。停开关不等于移除持久 App/reader/迁移；不得热装卸破坏历史。

P1 仅图片所需 Access/Card 子集；P3 按旧 09 BR01～BR13 验原生外置桥及故障；P4 验正式类型/Selection/编排，P5 验正式搜索/发现，P8 用中立第三种 Page、插件兼容和恢复验扩展。后续逐个可回退切片派工、明确文件所有权，不要求 P0 建齐所有 Provider。

## 待用户批准决定与未验证项

- Registry/ReadContext/SnapshotRef/四协议细化合同、单写者分工及错误/降级边界；不是以本文替代实施审查。
- U27～U36 已确认的产品选择不再重列待决；仅审定其未覆盖的本人草稿/只读/同父按组类型、集合跟随/固定及字段必填/空值等技术细则，以及批量/超时预算。资源分类按已确认公开交付原则落实；仅在确需受限签名时审定签名/撤销窗口，不新增首版复杂逐文件授权要求。
- 模块/App 命名、真实基础设施目标、后续配置/原型实施和真实操作授权仍独立取得。
- 未验证：全部接口、原生权限/动作入口、完整事务覆盖、标记冻结、Alias/复制/删除屏障、Outbox 可靠投递、索引写者、缓存与资源授权。旧审计不能当成本仓库实现事实。

## 风险与依赖

依赖 ADR-P0-01～07 的根包、身份、资源与固定图。高风险为可变 Revision 绑定、跨库假原子性、搜索泄漏、错误重试、权限陈旧、历史引用遗漏及插件停用破坏 reader。发布/删除/身份/事务边界若需改变，停止并升级决策，不临时绕过。

## 验证计划、停止与回退

- E1：文档交叉检查 U04/F16、模块单向依赖、各存储权威、错误/撤销及未决状态；不计为跨存储测试。
- E2：在获批实施范围内，项目导入前阻断 DB、网络、Storage、任务和子进程，仅受守卫装载并检查类型/注册冲突、协议错误分支及无具体 Page 反向依赖；不生成或执行迁移、不连真实服务、不开展 E3，Mock 不证明真实生命周期或事务。
- E3：具体授权后按切片验证原生后台入口、完整 Revision/Manifest、草稿/正式隔离、SQL 提交与 Outbox 原子性、重复/乱序/撤销、未知提交对账及 Mongo 零物理删除；图片局部不强制无关三库全量快照。
- Terra 主控整合与验收，Sol 提交架构提案但不自行验收；独立 Reviewer 负责关键跨存储、迁移、权限、Revision 及外置正文等高风险复核。本轮不派发子代理，也无独立复核结果。
- 停止：权威冲突、关键权限未知、无法覆盖原生入口、完整快照不一致、删除/身份/事务语义需要变更或任何越权 IO。
- 回退检查：保留版本、对象、操作身份/Outbox/删除屏障和引用证据；不靠 Mongo 物理删除、删共享资源、移除模型 App 或清空投影水位补偿。代码/服务/数据恢复须各自授权，不推送、合并或部署。
