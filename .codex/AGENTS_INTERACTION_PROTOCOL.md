# 新站多代理协作协议

本协议落实根目录 `AGENTS.md`。产品范围以 `说明书/00-产品需求与项目管理/00-README.md` 及其有效方案为准；角色配置不授予数据操作权限。

## 1. 角色与实际调度

| 角色 | 责任 | 允许的默认范围 |
|---|---|---|
| Terra | 主代理、项目总监、派单、整合、进度和验收 | 负责授权边界、文档同步、证据接收和最终验收 |
| Sol | 首席架构师 | P0 ADR、模型、迁移、公共接口技术方案；不自行验收 |
| Gemini | 工程开发 | 明确文件归属内的实现和定向测试 |
| 独立 Reviewer | 关键门禁复核 | 只读审查重大迁移、权限、Revision、外置正文、Outbox 和跨存储事务 |

使用 Codex 原生 `spawn_agent`、`send_input`、返回状态和 `close_agent` 进行实际协作。TOML 的 `model`、`model_reasoning_effort`、provider 或 nickname 只能作为声明，不能证明底层模型身份、权限隔离或供应商路由。

## 2. 派单合同

每次派单必须写明目标、已确认事实、未知项、获批范围、禁止操作、唯一文件归属、其他贡献者、环境与 IO 范围、成功证据、停止条件和恢复检查点。跨存储或高风险任务还必须写明数据权威、提交点、幂等、锁序、补偿和未知结果处理。

并行任务只能拥有不重叠的文件或只读研究边界。子代理不得继续派发子代理，不回退他人修改；同一工作树不并发执行 Git 写操作。审批按合同和风险分级：产品行为、持久身份、数据权威、权限边界和危险操作须由用户/授权人确认；普通内部类名、函数名、文件拆分和测试组织不逐项升级。

## 3. 验收证据

- 角色配置静态解析：只证明 TOML 结构和声明一致。
- 实际代理返回：只证明本次确实产生了协作返回，不证明模型供应商或隔离。
- 基础检查可包括 Python 语法、Django `check`、入口导入和协议/文档静态检查；完整 P0 E2 另须在项目导入前设置并验证禁止数据库、网络、Storage 和任务 IO 的守卫，并完成规定的装载和迁移图验证。
- E2 证据必须包含守卫的负向探针和违规计数；异常被业务捕获也不能视为通过。SQLite、LocMemCache 和“没有观察到连接”不是无 IO 守卫。
- E3 真实隔离服务、浏览器和真实用户态：必须另有具体授权、目标和记录。

报告要列出实际命令、环境、结果、跳过项和剩余风险。未知写结果先查持久化身份再重试；不得通过 fake、清库、覆盖或物理删除制造绿色结果。

## 4. 风险与收口

身份、权限、Wagtail Revision、发布/删除、Mongo 外置正文、Outbox 和迁移属于高风险边界。未完成必要合同或独立复核时保持“未验收”。用户未明确授权时不提交、推送、合并、迁移、建库、生产访问、服务重启或部署。
