## 3. 设计建议，不代表用户已选实现

- 用类型化 Registry/Provider 而非无约束字典，启动时检查类型键、版本、能力组合与依赖；Wagtail chooser 基础上增加动态筛选及服务端校验。
- TopicPage 作为有 URL/栏目语义的 Page；Series/FeaturedCollection 默认采用独立版本化 Snippet，需原生 Revision/发布/权限能力验证。需要独立路由时另评估 Page。
- 相关文章默认建议混合：人工顺序优先、自动补足且去重；数量及默认值待产品确认。
- 可复用集合默认建议跟随最新已发布版本，同时可提供固定版本引用；选择哪个策略及更新传播应显式确认，不许静默改变历史展示。
- 首次迁移技术路线 B 已由 U38 确认；独立 Git 仓库、最小 AbstractUser 方向及 U37 身份标识已确认。资源 AppConfig/label 已确认，Image/Rendition/Document 模型与迁移依赖仍为待实现/验证项。迁移 A 仅作条件备用，不机械复制项目或改第三方 label。P1 仅图片，文档业务在 P2a。
- 最小 Provider 合同草案已在 09 §14.2 形成：注册、Access、Card、Selection、Discovery、外置字段按 ReadContext/快照身份交互；当前权限不从历史恢复，候选/保存/前台分别验证。不要求每协议新建 App，尚未实现。
- 基于 U26/U37 已确认的最小 AbstractUser 及身份标识，所属初始迁移、组/权限依赖、反向关系和 Wagtail/第三方兼容须在首次迁移前核对并按 E2/E3 验证，不增加会员系统。
- 私有桶与受控交付是建议，需验证原生 chooser/预览/rendition/签名兼容；Collection 管理权限不等于前台保密。
- 编排 Page 目标推荐可空 FK SET_NULL + 稳定身份/编辑失效占位；复用集合及固定版本用受控退役/保留记录保护。具体策略经 P4 原生删除、Revision 重放验证后落实，不能只凭历史 JSON 外键认定已保护。
- 自动保存可能覆盖 Revision，绑定须带完整内容标记/代次；审核伴随证据冻结 Revision/内容标记/Manifest，同 ID 改载荷须重新审核。Alias 无自身 Revision，另定源绑定；keep_live 复制须有新完整绑定/正式指针/事件。以上都是待原生接入验证的合同。
- 删除使用独立于 Page 行存活的稳定 owner/删除屏障，迟到事件及同 ID/URL 重建不得复活旧内容；引用保护覆盖历史/固定集合/Alias/未决操作/预写/导入/Outbox，首版仅诊断，GC 不作异常补偿。
- Blog body 首版必填、intro 可显式空值是设计建议；字段缺失与空值不同。

本节中与 U27～U36 冲突的旧“待用户选择”已按最新确认收口：局域网公开访问、公开图片/附件简化交付、混合相关文章、精选集合跟随/固定两种模式、基础去重统计、登录评论、单中文站点和简单备份目标均已确认。剩余内容仅是技术细节、实现顺序和验收证据，不得再次要求用户重复选择。
- Markdown 导入由会话编排/类型装配负责，resources 只管资源摄取和引用；不是把全文解析及所有导入业务塞进 resources。
- MinIO 目标已按全桶私有、应用受控交付、专用受限凭据记录；Bucket 创建和真实权限验证仍需另行授权。
