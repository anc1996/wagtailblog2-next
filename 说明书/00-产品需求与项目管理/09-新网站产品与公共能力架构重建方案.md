## 1. 本次重新设计的出发点

按用户最新要求，将本项目作为一个使用独立测试资源的新网站重建。保留现有网站需要的前台展示与交互能力，重新设计数据模型、应用归属与页面接入方式。

旧模型、旧表名、旧 Mongo 文档结构、旧迁移链以及 Blog 专属服务不再约束新站目标结构。历史内容搬迁若以后需要，单独立项。新站能否运行、能否验收，不以迁完旧数据为前提。

可以复用经过核验的模板、样式、内容块、测试思路及局部算法，但须重新接入新契约。既有 `resources`、`people` 的 Blog 读取适配器，只是可参考的现有代码，不能作为公共实体已经建立的证据。

交付仍按小批次进行：先完成公共图片，再完成文档与资源块、人员、外置内容、正式页面、搜索、导入和其他前台功能。每批都要有独立的验证结果。

第二轮风险补强修订七份现有方案；当前 P0 设计续批仅修改 00/02/04/08/09/10 六份，01 与历史资料不变，10 只追加 §12。不修改业务、配置、模型或迁移，不导入项目/settings、不启动应用，不访问数据库或生产。全文状态标签含义：**已确认产品需求**为用户要求；**方案推荐**为尚可调整的技术选择；**当前源码事实**仅指静态核对；**技术待验证**尚缺原型或集成证据；**实现后待验收**是后续交付标准。第二轮事实证据索引见 [10 第 11 节](10-新站架构与AI团队审计报告.md#11-第二轮增量评审与风险补强)，本批设计及证据增量见 [第 12 节](10-新站架构与AI团队审计报告.md#12-p0-技术验证设计续批)，状态和最晚节点归 04，阶段门禁归 02。

## 2. 网站的产品结构

### 2.1 面向读者

读者可以浏览首页、博客、指南和作品展示，通过分类、标签、人员、归档及搜索发现内容；在详情页阅读正文、查看图片与图集、下载文档、播放音视频；使用评论、表态、订阅和联系表单。

新站保留现有前端的视觉资产、信息结构与用户可见能力。内部 API 和上下文字段可以调整，但不得将缺失功能悄悄替换成无响应的按钮或静态占位。现有入口是否保留原 URL，按前端清单逐项登记。

### 2.2 面向编辑

编辑仍在 Wagtail 中创建、编辑、预览、保存草稿、查看历史和发布页面。一个页面只有一套保存与发布操作，不要求编辑分别保存 MySQL 与 MongoDB。

图片、文档和人员在公共后台管理一次，BlogPage、GuidePage 及后续页面均可选择。Markdown 导入最终生成同样的草稿，遵循同样的校验、Revision 和发布规则。

### 2.3 面向开发者

新增一个页面类型时，只需定义其业务字段、公共能力声明、外置字段策略和页面模板，并补充接入测试。无需再复制 Blog 的 Mongo 存取、发布信号、搜索任务、媒体导入或补偿逻辑。

允许各页面保留必要的字段声明、关系中间模型和模板差异；公共化的目标是消除重复业务规则，不追求所有页面都塞进一张万能内容表。

## 3. 模块划分与依赖方向

采用 Django/Wagtail 模块化单体，继续使用现有技术栈。本方案不增加微服务、Docker 或新的消息系统。

| 模块 | 负责的能力 | 不应承担的职责 |
|---|---|---|
| `base`、`home` | 站点设置、导航、页脚、首页、公共模板和联系表单 | 正文版本与资源所有权 |
| `blog` | 博客页面、博客列表、博客专有规则和模板映射 | 图片、人员、搜索与 Mongo 公共实现 |
| `guides` | 指南页面、指南列表和指南专有字段 | 复制 Blog 生命周期 |
| `portfolio`、专题业务、`archive` | 作品页、TopicPage 和归档展示，各按业务职责装配 | 自行建立另一套正式正文读取流程 |
| `resources` | 公共资源实体/引用/授权、资源块、上传与资源摄取 | 页面发布权威、整个 Markdown 导入会话或全文业务解析 |
| 公共编辑器包 / `content_blocks` | Markdown、Mermaid、代码、表格、数学等编辑、净化与渲染协议 | 资源实体与文件授权、另一套页面发布系统 |
| `people` | Person、角色字典、页面人员关联的共享规则、人员主页 | 把“作者”写成博客专属身份 |
| `taxonomy` | 公共分类、标签及页面关联的共享规则 | 把所有页面类型的筛选字段强行合并 |
| `external_content` | 外置字段注册、版本、Manifest、Revision 绑定、发布协调与对账 | 替代 Wagtail 权限与工作流 |
| `search` | 注册、正式快照投影、Outbox、Delivery、建议词、搜索分析 | 充当正文或发布状态的权威 |
| `comments` | 页面评论、回复、审核与反垃圾 | 外置正文保存 |
| `engagement` | 页面表态、访问与阅读统计；初期作为一个公共应用 | 因统计失败阻断正文阅读 |
| `syndication` | RSS/Atom、分类/标签/人员订阅 | 从草稿或旧缓存拼接正式内容 |
| content_ai、observability | 可选 AI 辅助、日志与诊断 | 绕过公共保存和发布入口 |
| Registry / Access / Selection | 类型化能力、卡片与选择协议、原生访问规则适配 | 再造页面表、CMS 权限或发布状态 |
| Discovery / 编排 | 正式内容查询、可重建元数据、页面/集合有序引用规则 | 把所有关系放进一张万能表 |

以上是目标职责地图，协议是否独立成 App 随模型所有权、迁移依赖及代码规模确定，不要求第一批创建全部应用。无持久模型的编辑器组件可先作为 Python 包；媒体 Block 由 resources 提供，通用编辑 Block 不全部搬入 resources。`taxonomy`、`engagement`、`syndication` 在相应批次再建立，避免一次性搬空 Blog。

依赖方向为：

```text
页面应用 → resources / people / taxonomy / external_content 的公开契约
后台、导入入口 → 统一草稿保存入口
search、Feed、前台读取 → 正式快照读取入口
external_content → 声明式页面注册 + 资源引用协议 + 存储适配器
公共应用 → 不导入 blog.models，不按 BlogPage 类型分支执行业务
```

Wagtail 注册文件可以引用具体页面类完成装配；这种显式装配与公共服务内部硬编码 `BlogPage` 是不同边界。`external_content` 通过 Outbox 契约发出事件，不反向调用搜索视图或投影实现。

## 4. 存储与权威

| 存储 | 保存什么 | 权威边界 |
|---|---|---|
| MySQL | 页面树、短字段、关系、权限、Revision、Manifest、正式指针、资源元数据、导入会话和 Outbox | 页面与正式发布状态 |
| MongoDB | 带字段身份的不可变正文版本 | 指定版本的外置内容 |
| MinIO | 图片原件、派生图、文档、音视频二进制 | 指定对象的文件内容 |
| Elasticsearch | 已发布且允许搜索的内容投影 | 可丢弃并重建的查询副本 |
| Redis | 缓存、任务与有界协调状态 | 不决定发布是否成功，不替代持久化幂等记录 |

关系字段、筛选排序字段、权限字段和页面树关系保留 MySQL。长正文需要版本化时进入 MongoDB。是否没有多对多关系，不是外置的判断标准。

### 4.1 基础设施边界与分阶段接入

基础设施初始化方案独立记录在 [12 号基础设施与数据库初始化方案](12-新站基础设施与数据库初始化方案.md)。本节只固定架构边界，不代表资源已经存在、主机已经盘点或任何连接已经授权。

- `192.168.20.2` 仅是候选主机；服务版本、旧站/其他业务占用、端口、防火墙、容量、备份和 ACL 能力均须在 E3 只读盘点中核实，不能凭 IP 或建议名称推断隔离已完成。
- MySQL 在 P0-E3 首先接入，候选独立库为 `wagtailblog2_next_test`；应用、迁移、备份和基础设施管理员身份分离，应用不取得 DDL、授权管理或旧库访问。
- MinIO 为 P1 接入，候选 Bucket 为 `wagtailblog2-next-test`；本轮按全桶私有、应用受控交付和专用受限凭据作为建设目标；普通图片/附件只在明确公开时交给公开交付层，私有原件、草稿和后台资源不得因局域网部署而自动公开。
- MongoDB 在 P3 接入，候选独立数据库为 `wagtailblog2_next_test`，只保存已声明的不可变外置版本；Redis/Celery 按实际异步业务需要接入；Elasticsearch 在 P5 作为可重建投影接入。
- Redis/Celery 必须同时具备 ACL、key/channel/queue/route/result 命名空间；逻辑 DB 号、队列名或前缀单独存在都不是完整隔离证据。Elasticsearch 必须使用新站索引前缀、读写 Alias 和最小权限单写者。
- 真实盘点、建库/建用户/Bucket/ACL/队列/索引、迁移和服务验收均属 E3，须逐阶段授权；资源非空、名称冲突、归属不明、权限过宽或结果未知立即停止，不清库、不覆盖、不 fake、不使用旧站管理员账号。

第一版字段策略：

| 页面 | MongoDB | MySQL |
|---|---|---|
| BlogPage | `blog.body`、`blog.intro`，两个独立字段 | 标题、路径、日期、封面、分类、标签、人员关系、SEO 与其他短字段 |
| GuidePage | `guides.body` | 标题、分类、难度等短字段，以及讲师等关系 |

## 5. 公共资源设计

### 5.1 独立实体与 Wagtail 后台

新站建立 `resources.Image`、`resources.Rendition`、`resources.Document`。图片与文档分别沿用 Wagtail 自定义资源模型的原生抽象基类；派生图指向公共 Image，并保留原生规格与焦点相关唯一性约束。

新站配置从首次建库就将图片、文档模型直接指向 `resources`，最小公共 Image/Rendition/Document 声明随 P0 前置，图片业务在 P1、文档业务在 P2a 实现，避免建库后再次切换自定义模型。后台资源入口、chooser、Collection 和编辑权限沿用 Wagtail 原生能力。公共模型不能再导入或回读 `blog.BlogImage`、`blog.BlogDocument`。

音视频在后续批次建立公共 Media，并核验当前 `wagtailmedia` 的自定义模型、后台与块接入限制。Embed 是经校验的外链引用，不必为它建立与上传文件相同的二进制实体。

不先造统一 Asset 父表。不同资源保留适合原生后台的实体，共用上传、引用、权限和导入服务协议。

### 5.2 资源与页面的关系

- 封面：页面字段直接关联公共 Image，使用保护型删除约束。
- 正文图片：公共图片块保存资源标识与引用上下文。
- 图集：图集条目属于页面内容快照，图片实体独立存在。
- 文档块：引用公共 Document，下载经过权限入口。
- 同一张图片可被不同页面、不同正文位置复用，各引用分别保存 alt、说明、装饰性标记和排序。

资源标题等公共元数据与某次引用的 alt、图注分开。修改页面甲的图注，不应改变页面乙的图注。

原始文件采用不可覆盖的对象键。需要换文件时创建新资源并修改页面引用；首版不开放原地替换文件和物理删除。这样恢复旧 Revision 时不会指向已经被覆盖的另一份文件。

### 5.3 引用索引与回收

Wagtail ReferenceIndex 可用于后台展示和已支持字段的引用索引，但不能假设它完整覆盖 Mongo 正文、Markdown、历史 Revision 或导入中间产物。

公共引用记录至少标识：资源、页面身份、Manifest/Revision 或导入会话、字段键和块位置。不同资源使用可受数据库约束的关联，不使用任意字符串 URL 作为资源身份。正文版本冻结时同时生成引用清单，在保存 Manifest 的 SQL 事务内固化。

页面删除仍执行 Wagtail 原生 SQL 删除及其权限/级联规则，不能偷换为只撤销发布。删除前按保留合同保存稳定 owner、外置版本/资源引用及 tombstone 所需证据；SQL 外键置空/级联和历史保留结构须在 P3 验证。不能顺带删除共享资源，也不承诺原生删除后仍可恢复已被原生机制删除的 Revision。归档资源不再供新选择，已有合法引用仍能读取。自动回收必须等待独立的引用完整性与保留期验收；第一版只提供诊断和待回收清单。

**方案推荐：引用保护闭包**同时覆盖当前 Page、保留的 Revision、Manifest/Mongo 字段版本、固定的 Series/FeaturedCollection 版本、Alias 源/目标绑定、删除 tombstone、未绑定的 Mongo 预写、未完成或结果未知的 ContentOperation、待处理 Outbox 及 ImportSession 产物；对应 MinIO 原件和派生文件一并纳入判定。不能只扫描当前 live 页面后认定文件无引用。历史 Page/Revision 被原生删除时，必要的保留证据不得随同级联消失。以后获准回收须满足保留期、所有保护依据已解除及删除前再次核查；不把 GC 当作 SQL 失败补偿，第一版不自动物理回收。P3 验证记录闭包，P8 演练恢复与回收候选诊断。

**方案推荐：持久删除屏障。**不可复用的 `content_owner_uuid` 对应独立于被删 Page 的删除状态与删除代次，投递侧保留最后接受代次/水位。删除屏障、保留证据和删除事件在删除 SQL 事务中固化，不能只靠随后会消失的 Page 行或缓存。所有事件携带稳定 owner 与可比较代次；删除后迟到的旧发布、资源授权、归档和搜索事件不得恢复内容。屏障的保留/压缩期限必须覆盖事件重放、备份恢复及引用保留窗口，尚未证明安全前不回收。重新使用数值主键、slug 或 URL 的新页面取得新 owner，不能继承旧事件。

### 5.4 文件访问

U28 已确认首版私人局域网内采用简单公开交付：已发布公开页面中的图片正常加载，公开附件可直接下载，普通读者不需要逐文件登录或临时下载凭据。实现可使用私有桶与由新站负责的受控交付，须在 P1/P2a 验证原生 chooser、预览、rendition、缓存及第三方媒体兼容；后台、草稿、未发布、私有资源和原件保护仍按场景校验。公开资源一旦公开访问可能被保存，不能承诺随后转私有可以收回已下载文件。

Collection 权限主要解决后台管理，不等同于前台文件保密。文档直接输出对象永久 URL、只隐藏 chooser 按钮，都不构成下载鉴权。

首版不把逐文件签名、复杂用户授权或即时撤销作为普通公开资源的产品前提。若实现对私有资源使用内部签名或代理下载，签名残余窗口、私有缓存隔离和撤销语义仍须进入验收；公开页面的图片和公开附件交付可以按正式版本缓存。

### 5.5 ResourceAccessPolicy 场景合同

**已确认产品需求：**资源只有全站公共身份，不能由某个业务 Page 决定桶的全局 ACL；共享不应泄露受限内容，也不应因私有引用而阻止合法公开展示。

**方案推荐：**安全分类至少区分“可公开交付”和“受限”，派生文件显式记录自己的交付分类及来源。资源 ID、引用 ID、原件/派生标识、请求主体、场景、页面正式代次或授权预览凭证共同组成策略输入。Page 引用不自动改变资源分类；受限原件若要产生公开派生图，须经资源管理授权和脱敏检查，不能仅因公开 Page 引用就降密。公开图片被私有指南复用，不意味着图片本身获得新的保密承诺。

| 场景 | 允许条件与交付 | 撤销、缓存及真实验收 |
|---|---|---|
| 公开页引用可公开图片或附件 | 当前正式引用有效，输出允许公开的派生文件或附件；普通读者无需逐文件登录 | 缓存按对象版本/规格；公开 URL 不携带私有引用、人员或草稿信息 |
| 私有页引用同一可公开图片 | 先校验页面阅读权，页面卡片/图注独立保护；图片仍按自身分类处理 | 未授权不能读私有页及其引用配置，不能把公开图片存在性当作页面授权 |
| 公开页引用受限原件 | 不自动公开原件；拒绝不兼容配置，或选择已获准公开的独立派生文件 | 发布校验与运行时交付均检查，不能只在 chooser 隐藏 |
| 直接资源 URL，无 Page 上下文 | 可公开文件按自身策略直接交付；受限文件必须有独立文件许可或绑定主体/用途的有效交付凭证 | 猜 image/document ID、伪造 page_id 均不能授权；私有底层对象不能被永久 URL 绕过 |
| 私有文档直接下载 | 服务端校验资源政策及有效正式引用/独立授权；失败即拒绝 | 核对 Wagtail 文档入口、重定向和最终对象；普通 Collection 编辑权不自动给读者下载权 |
| 编辑预览尚未发布的引用 | 同时验证当前编辑/预览资格、预览快照及资源使用资格，不要求已正式发布 | 短期、绑定上下文；私有响应不进入共享缓存，伪造/过期预览拒绝 |
| 受限视频播放/Range | 每次新请求或短期受控会话重新鉴权；Range/HEAD/206/416 遵循相同政策 | 缓存不混用户；到期后的续段拒绝，原生播放器和断点续播真实验证 |
| 撤销页面、转私有或祖先权限改变 | 立即拒绝新的上下文授权；提升可见性代次，失效引用卡片/交付缓存 | 短签名有残余有效窗口，需明确上限；即时撤销选逐次鉴权，不能承诺收回已下载内容 |
| 删除 Page，但其他 Page 仍引用 | 仅移除该页面当前授权依据，其他合法引用继续读取 | 不删除共享原件；直接 URL 继续按资源政策判定 |
| 历史 Revision 引用旧文件 | 文件与引用证据按保留期保存；历史查看另校验后台/预览权限 | 恢复历史不恢复旧公开许可；原生删除可能级联 Revision，另存必要保留证据 |

**当前源码事实：**原生图片 serve 的规格签名未绑定页面/主体，默认响应有公开缓存；`rendition.url` 使用 storage 的 `file.url`。这两个行为本身不能提供上述上下文授权。原生文档存在 `before_serve_document` 接入及远程存储重定向路径；文档原生访问限制 hook 的完整组合本轮未核实，不据此声称原生文档没有限制。

Collection 的管理权限、chooser 候选过滤、资源使用资格和实际文件读取分别校验。chooser 过滤只是编辑入口的候选规则，不能作为引用、预览或文件交付的安全边界；不声称默认 chooser 自动保证所有 Collection 间的读取保密。

**技术待验证 / 实现后待验收：**P1 用私有 MinIO 桶实际验证 chooser 缩略图、图片编辑预览、rendition 生成/URL、浏览器与 CDN 缓存隔离、绕过交付入口、权限改变和重复请求；P2a 再验证文档及视频 Range。桶、Storage 签名、Wagtail URL 与交付视图必须一起验证。访问决策缓存须含主体/授权范围及当前权限代次，权限未知不复用旧许可。Collection 的后台权限检查和前台读取检查分别提供证据。P1 只落实图片所需子集，不提前实现视频系统。

## 6. 公共人员与分类

`people.Person` 表示人；作者、讲师、贡献者、编辑、专家和审核人表示角色。同一人可以承担多个角色。业务中的“审核人”展示角色不自动授予 Wagtail 审批权限。

页面人员关系至少包含 person、role、sort_order，必要时加入 is_primary 和 contribution_type。主人员的唯一性按页面和角色校验，不把所有角色限定为一个主人员。

关系必须参加页面 Revision。默认采用公共抽象关系基类与校验服务，再由 BlogPage、GuidePage 定义各自的 modelcluster 子关系，使用指向具体页面的 ParentalKey。允许少量关系声明重复，不能为追求一张关系表丢失历史恢复、复制与后台 InlinePanel 行为。

历史快照记录人员关联、角色和顺序；Person 的公开头像与简介默认展示当前资料。若要求“恢复文章时也恢复当年的人员简介”，另加显式资料快照，不声称普通外键天然具备该能力。

分类和标签按同样原则公共化：共享实体、共享规则，页面关系参加 Revision。博客和指南可以使用不同分类范围；指南难度等专有筛选项仍由 guides 管理。

## 7. 外置内容核心契约

### 7.1 页面能力声明

每种页面按需声明稳定类型键、能力、字段 codec/schema、卡片/访问/正式读取 Provider、编辑器和资源提取器；external_content 字段注册与通用类型 Registry 分工。无外置字段的 Page 不要求 Mongo 读写，公共注册不强迫其创建虚假 Manifest。启用外置字段的普通 Page，每个实际存在的 Revision 必须有完整绑定；原生 Alias 没有自身 Revision，采用下述独立别名绑定，不虚构 Revision。类型化契约详见第 14 节。

正文渲染块迁到公共块目录；页面仅选择允许的块及业务约束。新增页面类型用注册声明接入，不把 `isinstance(page, BlogPage)` 换个位置继续保留。

### 7.2 版本与 Manifest

一次保存形成一个完整 Manifest，Manifest 下按字段列出版本条目。字段未改变时复用该页面该字段已有的不可变版本；即使只改 SQL 标题，保存结果也有可追踪的完整 Manifest。**当前源码事实：**Wagtail 8.0 自动保存有覆盖同一 Revision 的路径，Revision ID 不能单独表示不可变快照。绑定必须识别 Revision 内容代次/摘要；Manifest 和 Mongo 版本仍不可变。

| 对象 | 最少身份与内容 | 约束 |
|---|---|---|
| 页面内容身份 | `content_owner_uuid`、页面类型键、环境命名空间 | 稳定且永不分配给另一页面；不依赖 Blog 表主键，不跨环境串用 |
| Mongo 版本 | owner、field_key、version_id、schema_version、codec、摘要与 payload | 写入后不可覆盖；身份、内容摘要与字段策略必须匹配 |
| ContentManifest | manifest_id、owner、类型键、schema 版本 | 完成后冻结 |
| ManifestField | manifest、field_key、version_id、摘要与 schema | 同一 Manifest 的字段键唯一；不允许缺项冒充空内容 |
| RevisionContentBinding | revision、page、revision 内容标记、manifest | 当前内容标记恰好对应一个完整 Manifest；覆盖自动保存时原子更新当前映射并保留必要绑定历史，禁止跨页面绑定 |
| ContentPublication | page、revision、revision 内容标记、manifest、generation | 与 Wagtail 正式发布状态同一 SQL 事务更新；不跟随可变的当前草稿绑定 |
| 审核快照证据（概念合同） | 原生工作流/任务身份、revision_id、revision 内容标记、manifest_id/摘要 | 冻结获审的完整快照；是原生任务的伴随校验证据，不声称 TaskState 已有这些字段 |
| Alias 外置绑定（概念合同） | Alias 稳定身份、源 Page/owner、源 Revision/内容标记/Manifest、源与 Alias 可见性代次 | 不复用普通跨页 RevisionContentBinding；无有效同步绑定的 Alias 不得读取外置正文，物理模型待 P3 验证 |
| ContentOperation | 操作键、目标身份、载荷指纹、状态与结果引用 | 持久化幂等与结果查询；同键不得绑定不同内容 |

`ContentPublication` 是普通外置 Page 的正式读取指针，其更新服从 Wagtail 发布生命周期。它不是第二个供编辑单独操作的发布开关。前台必须同时验证 Page 是否 live、当前正式 Revision/内容标记与该指针是否一致，以及访问权限。Alias 读取器显式解析受控源绑定，核对源快照、删除屏障及源/Alias 的当前资格，不强求不存在的 Alias Revision。内容标记如何随原生序列化持久化、自动保存绑定如何保留历史，是 P3a 阻断项；不能通过永远关闭原生自动保存解决。

**方案推荐：**Revision 内容标记覆盖本次完整 SQL 序列化内容、编辑关系和 Manifest 身份，不能只计算 Mongo 正文摘要。进入审核时冻结上述三元身份，完成任务、退回再审、即时发布和重试均核对该身份。若同 ID 的自动保存改变了内容标记，不得把审核资格移交给新载荷；拒绝该次发布并进入原生重新审核流程。保留旧 Manifest 不等于保存了被覆盖的 SQL 标题和关系，不能据此假装旧完整快照仍可发布。原生完成回调选取最新 Revision 的路径须通过受支持扩展接入，不能用“最新”替代“获审”。

示例：

```text
BlogPage / Revision 1001 / Manifest M1
  blog.body  → body-v7
  blog.intro → intro-v3

GuidePage / Revision 2001 / Manifest M2
  guides.body → guide-body-v2
```

Blog 的两个字段在一次保存中形成一个 Revision、一个 Manifest，并在一次发布中切换。第一版默认 body 必须非空；intro 允许显式空值，但仍须有字段条目。空值与字段缺失具有不同含义。该必填策略是本方案建议，见决策表。

版本身份包含页面和字段。第一版不做跨页面正文去重；复制页面时生成新的 owner 和版本身份，防止复制来源与新页面的内容所有权混淆。

### 7.3 编辑与 Revision 桥接

正文在 Wagtail 表单中正常编辑，SQL Page 和 Revision JSON 保存元数据及 Manifest 引用，完整外置正文不再作为第二份权威正文写回 SQL。

表单校验、Revision 序列化/回填、预览、历史比较、恢复、复制、工作流和定时发布均须显式接入桥接层。不能仅在 `save()` 或发布信号中补写 Mongo，就认定生命周期完整。

P0 先完成安装版本 API 调查、可接入位置与未覆盖路径清单，P3a/P3b 再以真实原型证明，不把接入调查拖到开始实现之后。P3 未通过前，不将正式 BlogPage 切换到新链路；本方案没有把未经验证的自定义外置字段 API 当作框架既有能力。

### 7.4 一次保存与发布

草稿保存：

1. 验证页面权限、表单、字段策略和请求指纹，预留可查询的操作身份。
2. 用稳定 owner/字段身份预写不可变 Mongo 版本；新建页面可以先分配 owner UUID，尚未生成 SQL 页面时的版本属于待绑定产物。
3. 在 SQL 事务内，已存在 Page 按固定顺序加锁，检查基准 Revision ID 及内容时间/代次，保存元数据、完整 Manifest、资源引用、Wagtail Revision 和绑定，并标记操作结果。首次创建不能锁不存在的 Page，须按原生树插入取得主键后完成绑定，并对父节点/幂等身份的协调单独验证。
4. SQL 提交成功后才返回保存成功。Mongo 预写成功而 SQL 回滚时保留未绑定版本，登记待对账。

发布：

1. 针对选定 Revision 的完整 Manifest 校验字段、版本身份、摘要和资源引用；不使用“最新 Mongo 文档”。
2. 在受控 Wagtail 发布事务中锁定 Page，重新核对选定 Revision 的内容标记/Manifest、被冻结的审核或排程快照及当前资格，避免使用加锁前已经物化的陈旧对象；更新原生发布状态和 `ContentPublication`，递增 generation，同事务写 Outbox。同 ID 改载荷、不同 Revision 替换、失效审核均不得静默通过。
3. 提交后失效缓存并异步投影。搜索暂时未更新不改变发布结果，前台正文按正式指针读取。

锁顺序固定为 Page → 发布/操作状态 → 关联写入；批量操作按页面 ID 排序。Mongo 网络读取放在有预算的预检阶段，事务内复核不变身份，避免长时间持有 SQL 锁等待外部服务。

预留操作状态与业务提交可以是不同事务；只有最终提交事务产生的结果才表示业务完成。操作结果未知时按操作键查询或对账，不能换一个键盲目重复发布。

### 7.5 生命周期矩阵

| 操作 | 默认行为 | 必须证明的边界 |
|---|---|---|
| 保存/自动保存 | 建立可识别的草稿快照 | 不改变正式指针，不把自动保存写成发布 |
| 草稿预览 | 授权后读取指定草稿 Manifest | 不使用公共缓存，不进入正式搜索 |
| 历史查看/恢复 | 读取旧绑定；恢复产生新的草稿 Revision | 按字段恢复，资源与人员关系一致 |
| 工作流审批 | 原生任务伴随证据冻结 revision_id + 完整内容标记 + Manifest；原生默认完成回调会重新取最新 Revision | 审核 R1 后同 ID 自动保存覆盖或出现 R2 均不能挪用旧审核资格；加锁复核、退回再审/重试/重启，不宣称 TaskState 已原生冻结三元身份 |
| 定时发布 | 执行排程指定 Revision 及其内容标记/Manifest | 不发布执行时“最新正文”；同 ID 内容已变也须拒绝失配排程并给出可修复状态 |
| 复制 | 新 owner、字段版本身份、Manifest 和完整 Revision 绑定；共享合法二进制资源 | 普通/历史/子树复制独立编辑；keep_live 也必须在经过验证的原生发布协调中提交新 ContentPublication/Outbox 并复核权限，不能只设置 live |
| 别名 | 无自身 Revision；独立 Alias 绑定引用源 owner/Revision/内容标记/Manifest，保留 Alias 自身可见性代次 | 尊重原生同步；默认同时核查源与 Alias 当前访问，跨 Site/祖先限制不自动继承或放宽。源发布/撤销/删除和乱序同步均需验证；解除别名生成新 owner/Manifest/有效 Revision/正式指针，不跨页借用普通绑定 |
| 移动/调整栏目 | 沿用原生树操作；正文 owner 和已有不可变版本不因路径变化重建 | 核验新祖先的权限/私有限制、Site/URL 及子树影响；更新受影响投影和缓存，不只刷新被移动根节点 |
| 撤销发布/转私有 | 同事务更新可见性、代次并写事件 | 缓存、搜索、Feed 和资源交付均服从新状态 |
| 删除页面 | 原生 SQL 删除；同事务固化不依赖 Page 行存活的稳定 owner/删除屏障、保留证据和事件 | 批量/子树/级联、提交断连、迟到事件及同 ID/URL 重建均须证明不复活；不改为仅软删除，不顺带删共享文件或在异常中物理删 Mongo |

撤销、删除与权限变化也要检查所有入口，包括后台批量动作、管理命令及后台任务，不能只覆盖详情编辑页按钮。

### 7.6 原生桥接的最小技术验证计划

**方案推荐：**使用声明两个外置字段和一个外置字段的最小真实测试 Page，复用最终目标保存/发布合同；不得用测试替身绕过原生视图、Action 和任务。P0 输出入口清单、序列化草图、锁序、失败注入点、隔离资源及预期断言；不创建模型、迁移、库或写入数据。下表实验在另获具体授权后执行。

| 编号 / 阶段 | 安装源码已识别的入口或风险 | 最小实验与通过断言 |
|---|---|---|
| BR01 / P3a | create 先 `add_child` 获主键，再 `save_revision` | 初次创建与失败重交：owner 可预分配，SQL 页/Revision/完整绑定同时成功或回滚；无不存在 Page 的锁 |
| BR02 / P3a | `save_revision(overwrite_revision=...)` 可覆盖；编辑并发检查含 ID 和时间 | 自动保存、普通保存、两标签编辑竞争；完整内容标记覆盖 SQL 元数据/关系/Manifest，同 ID 不同内容能辨认，旧正式指针和冻结审核快照不被改绑 |
| BR03 / P3a | modelcluster 仅按声明字段/关系序列化 | body/intro 独立修改、仅改标题、显式空/缺字段；完整 Manifest、资源引用、摘要可回读，SQL JSON 不含完整正文 |
| BR04 / P3a | `Revision.as_object → with_content_json`；历史对象的 latest_revision 可为当前最新 | 历史预览、比较 live 与历史、恢复旧版本后保存新草稿；以所请求 Revision/内容标记读绑定，不能按 latest_revision_id 取正文 |
| BR05 / P3a | 无未发布变化时 latest-object 可直接返回 SQL specific | 正式读取和编辑回填均正确；未走历史反序列化时也能装载正式外置字段 |
| BR06 / P3b | TaskState 有 revision；默认完成回调重新选最新 | 审核 R1 后同 ID 覆盖或出现 R2，立即完成/拒绝/退回重审、不同审核组及重试/进程重启；锁后验证冻结三元身份，只发布获审完整快照，失配须重新审核 |
| BR07 / P3b | 后台可直接构造 PublishPageRevisionAction；Action 构造时已 as_object；存在排程分支 | 即时、未来排程、到期命令、重复发布、取消/替换排程及同 ID 改载荷；指定快照与正式指针/Outbox 原子一致 |
| BR08 / P3b | copy 历史可直接 `Revision.save`，keep_live 直接设置状态 | 普通/历史/子树/保持 live 复制均有新 owner/字段版本/Manifest/Revision 绑定；keep_live 经原生发布协调在同 SQL 事务生成正式指针/事件。测试私有/未发布源、独立编辑与源删除；无法覆盖即阻断 P3 |
| BR09 / P3b | alias 无自身 Revision，源同步携带源 Revision；解除 alias 调用 save_revision，若页面 live 则随后直接更新 live_revision | 验证独立 Alias 绑定、源发布/撤销/删除、不同 Site/祖先限制、缓存及重复乱序事件；无效绑定不得读正文。解除别名新 owner/Manifest/有效 Revision/正式指针，可独立编辑；单独包装 save_revision 不证明随后正式指针及事件原子一致 |
| BR10 / P3b | move 更新子树 URL 不逐页 save；祖先限制可变化 | 移动跨栏目/站点及改变祖先权限，全部受影响后代的访问、投影和缓存可收敛，正文身份不变 |

## 8. 搜索、前台读取与缓存

搜索注册包含页面类型、站点范围、允许索引条件、投影字段和正式读取器。Blog 的 title、intro、body 可以合并用于检索，但投影保留来源字段与 manifest/revision 标识。

默认仅索引可公开搜索的正式页面。私有页面不进入公共索引。Outbox 在业务 SQL 事务内创建，Delivery 记录投递结果；消费者读取当前权威代次，按目标页面串行化或使用已验证的版本条件写入，拒绝旧事件覆盖新状态。重建任务使用相同适配器与代次规则。

Search/Delivery、Archive、Feed、缓存回源、资源授权、对账和未来 GC 均遵守第 5.3 节的稳定 owner/删除屏障；Page 行不存在不能被解释成可重新发布的空状态。投递水位不能随着投影重建而丢掉删除事实，备份恢复后先追平删除屏障再开放正式读取；处理结果未知先对账，不能重放旧发布来“修复”缺页。

索引是最终一致的。搜索结果返回之前，必须批量回查 SQL 的发布状态、权限与正式版本；旧版本的标题、摘要、高亮也不得直接返回。建议词、搜索统计、数量和 Feed 不得绕过该校验泄露已撤销内容。校验后页内数量不足可以有界补取，不能无限回查。

页面详情、搜索投影、Feed 和导入回读共用正式快照读取器。缓存键包含站点、页面、正式代次和适当的访问范围；公共与预览缓存隔离。Redis 失败可以回源，但必须有并发与耗时限制。

Mongo 正式版本缺失、Manifest 不一致或权限无法确定时，返回明确不可用并告警。不能回退草稿、旧 Blog 存储或“最近一个能读到的版本”。可选评论计数、推荐、统计或搜索故障可以按各自契约降级。

## 9. Markdown 与媒体导入

导入编排层负责 Markdown 解析、ImportSession、步骤推进和结果查询；类型装配器负责目标类型、字段映射和业务校验；`resources` 负责资源发现后的抓取/摄取、创建、引用和资源产物跟踪。公共 Markdown 编辑/渲染模块负责其语法与净化，不能把整个内容导入器塞进资源服务。导入最后调用与后台相同的草稿保存契约，不将 BlogIndexPage 固定为唯一导入目的地。

ImportSession 记录操作身份、来源摘要、目标页面类型、阶段、创建的资源和最终 Revision。相同幂等身份不能改绑另一份正文；修正校验错误后用新的提交身份，不能覆盖已接纳操作的指纹。

远程 URL 做协议、地址解析、重定向、私网目的地、大小、MIME 和超时校验，禁止抓取任意内网资源。脚本与后台入口均要认证、CSRF 或等价请求防护及对象权限。Markdown、富文本、SVG 与 Embed 按各自信任边界净化、转义或限制，不能将外部导入内容直接标记为安全 HTML。

失败时，共享或已有资源保持不变；本会话新产物标记待对账，首版不自动物理清理。MinIO 上传超时不能证明对象不存在，重试前按会话和对象身份核验。AI 生成内容仍是待审核草稿，不绕过发布。

## 11. 故障、恢复与运维

- 外部调用设置连接、读取和总预算；只对已证明幂等的瞬时故障有限重试。
- 并发保存使用基准 Revision/代次检查；冲突返回编辑提示，不静默覆盖。
- Outbox 重复、乱序、延迟、任务重启均须可重放；死信和积压可诊断。
- 日志记录操作、页面、Revision、Manifest、代次及错误分类，不记录正文或凭据。
- SQL 是恢复关系与正式指针的主线；随后核验其引用的 Mongo 版本和 MinIO 对象，最后重建 ES、缓存与派生图。可恢复的派生图不是原件备份。
- 备份须覆盖 SQL 与其引用的不可变 Mongo/对象版本；只备份某一库不构成完整网站备份。恢复点、日志水位、暂停或增量追平策略在恢复演练前确定，不能声称不同时间随意备份即可一致。
- 首次公开上线前必须进行隔离恢复演练，并记录可接受的数据损失和恢复时间；数值由实际运维要求确认，不能先写成已达成指标。

## 14. 原生 CMS、身份权限与插件协议

### 14.1 原生负责与公共扩展负责

Wagtail 原生负责 Page Tree/栏目、创建/移动/复制/别名/删除、Draft/Revision/比较/恢复/预览、Workflow/Tasks、排程/发布/撤销、用户/组/页面树权限，以及 Panels、StreamField/StructBlock/ListBlock、InlinePanel/Orderable/ParentalKey、choosers、Snippets、Collections、Site Settings、图片/文档、Redirects、Forms 和适用的 Site/Locale/API。多站点、多语言及 API 接入按需求和版本验证逐步启用，不一律纳入首批。

公共自定义部分解决本项目的类型能力、卡片/选择/发现、资源引用保护、外置字段桥接、统一实时互动、索引投影及 AI 策略。优先通过正式 Hooks、Panels、ViewSets、Blocks 和 Django App 装配；不修改 Wagtail Core，不另做一套 CMS 用户、审核和发布。

用户已确认采用继承 AbstractUser 的最小自定义 Django User（04 U26/U37），保留原生认证、组与权限，首版不增加会员、支付、订阅或业务资料字段。P0-DEV-01 已创建并装载身份模型，但未生成迁移；首次迁移依赖和 Wagtail/第三方兼容按 §10.2 继续验证。Person 是作者/讲师等展示身份，后台 User 是认证身份，两者按需关联且不自动授予编辑或阅读权限。

原生私有页面限制、祖先限制、登录/组访问、Site/Locale 与自定义未来授权组合成 Access 协议。原生后台 page permission 与读者 can_view 分离；不能以 `.live().public()` 代替所有访问情形，也不能让外部 Provider 扩大原生许可。公共匿名查询仅接纳确认公开的页面；有请求上下文的受限读取必须验证实际访问规则。权限未知按边界失败，不默认为可读。

本期仅保留简洁的 future entitlement 扩展点。会员、套餐、订单、支付、退款、续费、会员中心和计费全部排除；不预建这些表。

### 14.1.1 后台角色与原生权限场景矩阵

**已确认产品需求：**按栏目管理创建、编辑、审核和发布；后台编辑权与前台阅读权分开。下表是原生 Group/Page Permission/Workflow/Collection 的**方案推荐**组合，角色名不是另建角色数据库，也不意味着互斥或自动授权。

| 角色 | 原生配置与允许操作 | 必须限制与后续验收 |
|---|---|---|
| 网站管理员 | 必要的站点/组/工作流配置，特权账户按实际职责分配 | 不把所有日常人员设 superuser；跨栏目、用户及资源授权有可追溯配置 |
| 栏目负责人 | 指定树根 add/change，按需 publish/锁与工作流管理能力 | 不管理兄弟栏目；移动到别处后重新判断继承权限和读取限制 |
| 博客作者 | 博客栏目 add，按投稿模式授予最少编辑权；允许子类型另由页面类型约束 | 不可在指南栏目建 BlogPage；不能靠注册能力绕过父子类型限制 |
| 指南作者 | 指南栏目 add/必要 change，页面模型约束允许类型 | 不得在未授权位置创建 BlogPage/GuidePage；两组重叠时按合并权限复核 |
| 普通编辑 | 指定子树 change；publish 按需单独授予，删除资格按原生权限组合核对 | 能编辑不等于能发布；删除并非独立 Page delete 授权，不得修改无关页面或私有预览 |
| 审核员 | 指定 Workflow 的 GroupApprovalTask 组及必要后台/对象可达权限 | 只审核指定任务范围；未额外授予无关栏目 publish；“可进入编辑器”与“可修改/发布”分测 |
| 资源管理员 | 指定 Collection 的图片/文档操作权限及后台访问 | 不自动获得 Page 编辑权或受限文件的前台公开授权；不允许本期物理删除 |
| 指定内容处理/只读人员 | 菜单、ViewSet/对象级检查及最小后台入口 | 原生是否能满足任意“只读指定对象”未证明；不能只隐藏菜单，直连编辑/动作请求也需检查 |

**当前源码事实：**Page 权限检查组合树范围、add/change/publish、owner、任务等。`can_edit` 包含 change、add + 本人 owner 或任务授权分支，add + owner 不等于“只能编辑自己创建且仍为草稿”。`can_delete` 对非叶节点要求 bulk_delete；change 分支在没有 publish 时拒绝含 live 页的删除，add 分支还核对本人 owner 及后代条件，没有 publish 时要求后代属于本人且未发布。`can_move` 复用删除资格并结合目标位置检查，不能只授予目标 add 就认为可移动。以上是权限方法的静态事实，仍须通过各实际动作入口验证。

Person 作者关系不等于 Page.owner。Page 的允许父子类型限制通常是类型级规则，不自动表达不同角色的类型白名单；若同栏目需要按角色细分，须通过原生扩展点和服务端校验补足。原生 `can_publish` 单项判断不等于全部 Workflow/锁/动作校验已经执行。

| 操作场景 | 必须用真实后台/数据库证明的边界 |
|---|---|
| 投稿者仅本人草稿 | 分别测试 add+owner、change、已发布页/退回稿、任务授权、owner 变更；若需额外限制，用统一对象级扩展，不能宣称原生自动满足 |
| 指定审核范围 | 对象关联 Workflow、任务组、可达页面与独立发布许可分别配置；R1/R2 并发见 BR06 |
| 移动及祖先限制 | 源端删除/移动资格、目标 add/子类型、live 子树发布约束及新祖先的读者限制一起测试 |
| 复制/别名及解除别名 | 原生权限方法不保证逐后代核查，也不保证继承源祖先全部限制；目标树、子树、站点/语言与访问策略必须实测 |
| 定时及批量操作 | 校验创建排程时与执行时的授权政策；单页、批量、子树不能绕过服务端对象检查 |
| 只读后台与资源操作 | 直连 URL、POST、chooser、批量动作、API 与 Collection 越界分别验证；不把按钮可见性作为权限证据 |

**技术待验证 / 实现后待验收：**P0 形成角色组及动作合同；P1 验证资源权限子集，P3 验证生命周期入口，P4 验证正式栏目和页面类型，P7 收口原生登录交互。额外限制只填原生缺口，不创建另一套 CMS 权限权威。未来会员权益只通过 access 接口接入。

### 14.2 能力注册与模块通信

以下均为**方案推荐、尚未实现的项目协议**，不是 Wagtail 内置 API。本次补齐最小输入、输出和失败语义，具体 Python 类型及方法签名在获授权实施时以该合同细化，不要求现在建立全部服务。

`ReadContext` 至少包含站点、语言、主体/已验证访问凭证、purpose（卡片/正文/选择/资源/发现）与 mode（正式/受限正式/授权预览）。`SnapshotRef` 标明通用 Page/稳定 owner、原生 Revision、内容标记及可选 Manifest/正式代次；非外置 Page 的 Manifest 可空。前台正式读取不能接受调用者任意指定 Revision 来替换正式快照；预览须验证实际对象、Revision/内容标记/Manifest 组合和当前预览资格，不能仅凭 revision_id 放行。访问凭证不得进入日志或共享缓存键。

| 契约及候选操作 | 输入 → 输出 | 校验边界 |
|---|---|---|
| `ContentTypeRegistration` / resolve | 稳定 type_key、模型引用、协议版本、能力枚举、Provider 声明 → 不可变注册描述 | 启动检查重复键、模型解析、能力/Provider 配对、版本和依赖；具体类型只在自身装配层注册 |
| `AccessProvider` / evaluate_batch | Page 身份列表、ReadContext、预期 SnapshotRef → 逐项访问决定及已核对快照 | 当前原生发布/祖先限制/站点/语言为依据，前台阅读与后台编辑资格分开；不能把 live 布尔值或 Collection 管理权单独当作许可 |
| `CardProvider` / load_batch | 已核对的 SnapshotRef、ReadContext → PageCard 或明确失败 | 卡片含 Page/type_key、正式标题/摘要/日期/URL、站点/语言和受控封面引用；不可回退最新草稿，不输出私有对象键或未经授权的 Storage URL |
| `SelectionProvider` / candidates、validate_batch | featured/related/topic/series 等场景、所有者/目标身份、编辑上下文/顺序 → 有界候选或校验结果 | 按能力/站点/语言/权限校验，拒重复和自身关联；允许合法草稿引用不等于允许前台显示；动态 chooser 和保存端均校验 |
| `DiscoveryProvider` / query | 类型/日期/站点/语言过滤、排序、游标及 ReadContext → 有界正式快照页 | 投影可过期，逐项复核当前访问；总数/摘要/高亮/建议词不旁路权限，无全表实时年月扫描 |
| `ExternalFieldRegistration` / validate、decode | 字段键、Codec/schema、原始载荷或版本身份 → 可校验字段值及资源引用 | 保留旧 reader；不支持版本明确失败；可选外置能力不决定发布资格，不改变原生 Revision 权威 |

访问判断与内容读取使用同一快照身份，不能用 R1 的授权加载 R2 的正文/摘要。读取期间正式代次或访问范围变更时复核并有界重试；无法取得一致状态返回明确失败。历史内容只恢复内容与编排，不恢复过去访问许可；移动后的祖先限制、撤销及转私有按当前原生状态复核。权限缓存必须有已验证的失效/代次机制，未证明正确前不靠陈旧投影或许可缓存放行。

选择有三道独立校验：chooser 候选、POST/保存、前台读取；不能用第一道代替后两道。保存由父 Page/版本化 Snippet 的原生编辑事务与 Revision 承载，Provider 不自建发布系统；目标失效/删除及集合传播以 §15.4 为准。访问拒绝的内容不向调用者提供卡片元数据，授权后台才可见可修复失效原因。

| 内部结果 / 错误类别 | 处理合同 |
|---|---|
| `NOT_FOUND` / `UNREGISTERED` / `UNSUPPORTED` | 区分不存在、未注册与能力不支持供诊断；公开响应合并为无可展示项，不暴露受限对象是否存在 |
| `DENIED` | 不返回卡片/内容/封面；原生登录/口令挑战可按路由处理，不把拒绝解释为空正文 |
| `UNKNOWN_ACCESS` | 明确拒绝受限读取，记录脱敏原因；不是“允许”，也不能静默跳过鉴权 |
| `UNAVAILABLE` / `INCONSISTENT_SNAPSHOT` | 正文或关键权限失败明确不可用；可选推荐按契约降级为该组件不可用，不能回退草稿或旧授权 |
| `INVALID_SELECTION` / `VERSION_CONFLICT` | 保存端给出可修复错误，避免部分保存和覆盖新版本；前台不输出后台诊断或私有目标信息 |

方法提供有界批量读取、页长/候选数/外置读取预算与超时，先筛身份再批量取必要字段，避免逐卡片 N+1 和无界重试。缓存隔离站点、语言、正式快照与访问范围；预览不进入公开共享缓存，资源凭证由交付层按当前授权生成。

能力键使用受约束枚举/类型对象和 schema，不以任意字典的 `True` 声称后台/权限已实现。公共服务仅依赖协议和通用 Page 身份，不按 Blog/Guide `isinstance` 分支；依赖检查允许装配层与具体 ParentalKey 模型的显式关系。P0 只审合同与测试设计，P1 实现图片所需访问/卡片子集，P4 验编排、P5 验发现投影、P8 用第三种 Page 证明扩展，无须 P0 实现所有 Provider。

同步 Provider 适合权限、卡片和选择；生命周期协调适合必须同事务的 Revision/正式指针；异步事件适合索引、增量归档、缓存、Feed 和通知。Outbox 至少带 event_id、page_id/owner、type_key、正式 revision/manifest（不外置时 manifest 可空）、generation、schema_version 和操作种类；删除事件不依赖已删除 Page 才能解读。消费者幂等、拒绝旧代次、有限重试并可诊断，不读取任意最新草稿。

核心事务内只执行必要、受控且经过验证的参与者；可选插件消费已提交事件，不能凭任意 Hook 改写正式状态或在事务内发外部网络通知。`on_commit` 唤醒失败不能丢掉持久 Outbox，后台扫描可恢复投递。

插件描述身份、版本、兼容协议/框架版本、依赖、权限范围、数据所有权、配置、故障及升级/停用边界。第一版是模块化单体和受控功能开关；不做插件市场/在线 ZIP/任意热装卸。停止功能先停入口/消费者并保留数据/历史引用，移除模型和迁移是另行评审操作；功能开关不等于卸载。可选推荐/评论统计故障可降级，关键访问和内容不一致不能降级为放行。

### 14.3 插件升级、停用与历史兼容合同

**已确认产品需求：**插件迭代不能无故损坏正式内容、历史 Revision 或预览；本期只建设稳定协议、依赖约束和扩展测试，不开发安装管理器。

| 等级 | 示例与数据所有权 | 关闭/升级边界 |
|---|---|---|
| 一级：展示与纯功能 | 卡片样式、可选推荐算法，无自己的持久模型 | 可停新入口/算法并用约定展示回退；若存在持久 Block 类型，不能仅按纯展示处理 |
| 二级：持久业务 | 评论、系列、精选；拥有自有模型/迁移/事件 | 关闭入口仍保留模型、表、历史读取与依赖；清理/删表/移出 App 另行专项审核 |
| 三级：核心生命周期 | Codec、Revision 绑定、发布协调、Access、资源引用 | 缺失或不兼容时拒绝受影响写入/发布；保留安全读取或明确不可用，不能回退草稿/越权，也不能任意热停 |

最小状态建议为 **启用 → 停止新写但兼容读取 → 停用业务入口但保留兼容依赖 → 经专项审核退役**。重新启用先检查版本、积压事件、schema 和依赖，再恢复新写；不重建或清空既有数据。状态只是发布/运维合同，不要求本期建插件状态数据库。**关闭功能开关不等于可从 `INSTALLED_APPS` 移除含模型和迁移的 App。**

| 合同项 | 最小规范及失败边界 |
|---|---|
| 身份/名称/初始化 | plugin_id、type_key、Block 名与 Codec 键稳定；展示名称可改，持久键更名要兼容映射；依赖 DAG/初始化顺序显式声明，重复/缺依赖在启动检查失败 |
| 版本与 API/Provider | 声明 Django/Wagtail/插件/协议兼容区间；破坏性契约升主版本，保留适配窗口与测试，不以同名接口静默改语义 |
| 数据及迁移 | 插件拥有其表/模型/历史迁移，公共资源只引用；追加有版本迁移，跨插件依赖显式，不根据功能开关改变迁移图 |
| StreamField Block | 持久 block type 与 payload schema 独立版本；保留旧定义/兼容解码器和原始数据，升级、降级或名称映射均需 round-trip 样例 |
| Mongo Codec | 不覆盖旧 payload；旧 schema 保留解码能力，升级生成新版本/Manifest；无法识别时保留数据并阻止破坏性重存，不能当空内容 |
| 停用后的读取 | 已发布页/历史预览使用兼容 reader；只允许声明过的安全占位，不执行未知脚本；关键正文不能读时明确不可用，不能静默丢段 |
| 重新启用/事件 | 检查停用期间事件水位、去重、代次和旧事件 schema；有界重试/死信，隔离不兼容事件，不盲目重放未知写结果 |
| 退役/卸载 | 查当前/草稿/历史/Mongo/集合/资源及迁移依赖；先做可验证替换/导出、保留与恢复合同，再另行授权退役；引用未清楚时禁止物理卸载 |

**当前源码事实：**Wagtail StreamBlock 有按已知子 Block 名过滤数据的路径，不能假设删除 Block 定义仍能无损读取再保存。**技术待验证：**SQL StreamField 和 Mongo Codec 都须测试旧 type、旧 schema、未知 type、改名、关闭入口、重新启用和重复事件；验证前后 payload/引用/渲染与 Revision 绑定不丢失。P0 定兼容政策，P2/P3 随对应能力建立样例，P8 做升级/停用/再启用真实扩展验收；不把任意第三方插件自动纳入支持范围。

## 15. 公共选择、内容编排及组织体系

### 15.1 通用 Page 引用与 chooser

关系目标优先引用 `wagtailcore.Page`，按 Registry 校验场景能力、类型、站点、语言和编辑权限。原生 PageChooser 提供基础 UI；动态注册过滤、搜索列表、候选卡片及服务端保存校验需定制并测试，不能写成 Wagtail 默认已支持。

选择时展示草稿/未发布状态提示；发布父页面可以保留尚未公开的引用，但前台必须过滤，不能由父页面发布连带发布目标。读取时批量加载当前目标状态和正式卡片，限制查询数及外置读取次数；拒绝跨页权限污染和 N+1。

### 15.2 各种编排的 Revision 归属

| 场景 | 关系/内容归属 | 发布与更新语义 |
|---|---|---|
| 首页人工精选文章轮播 | HomePage 的具体 ParentalKey + Orderable，目标通用 Page；标题/封面覆盖、启用/展示配置 | 引用顺序和配置随 HomePage Revision 保存/预览/恢复/发布；目标卡片取当前正式内容，父快照不冻结目标发布资格 |
| Blog/Guide 相关文章 | 公共抽象关系规则 + 各类型具体 ParentalKey 子关系；模式/条数归父 Page | 禁自身、重复和非法目标，父 Revision 决定人工关系；自动推荐由正式 taxonomy/Discovery 计算，混合时去重补足 |
| 页面普通图片/频道精选轮播 | 该页面的内联关系/展示配置 | 随所属 Page Revision；资源引用与内容引用可用不同关系表 |
| 正文画廊/轮播 | 公共 StreamField Block | 外置时块和资源引用属于字段 Mongo 版本/Manifest；SQL 正文按原生 Revision；不另外保存一套实时关系 |
| 可复用精选组件 | 版本化 FeaturedCollection Snippet 及其有序子关系 | 自己草稿/Revision/发布；父页面存集合引用及选择的传播策略，见下表 |
| 未来音视频轮播 | 媒体引用 + 可复用播放器/组件 | 归属同上述场景，处理/转码状态不自动发布页面 |

轮播共享卡片/资源服务、前端组件与无障碍规范，不强迫同用万能关系表。封面覆盖仅存公共 Image 引用；覆盖标题/摘要需要明确是编辑的父配置，不能以此泄露不可访问目标。旧画廊保留图注、初始条数/加载更多等行为；是否调整数量在前台对账确认。

首页人工精选与自动热门有独立数据、展示区和开关；热门不能覆盖人工排序。旧首页 `view_counts__count` 与 `view_count_v2` 先确定统计规则，再建设跨类型榜单，不能求和回填。

相关文章保留手动、自动、混合三种策略；建议默认混合（人工优先，按规则自动补足且去重），默认模式、条数与跨站/跨语言范围未获用户最终选择。不允许自动推荐绕过当前访问检查。

### 15.3 栏目、专题、系列和精选集合

| 对象 | 建议原生机制及原因 | Revision、权限与传播 |
|---|---|---|
| BlogIndexPage/GuideIndexPage | Page Tree 栏目，有 URL 和子页面约束 | 原生页面树及编辑权限；栏目不等同 taxonomy |
| 分类/标签 | 公共 taxonomy 实体 + 类型范围/规则 | 页面关联参加 Revision；分类更名传播当前展示，若需历史名称快照另设合同 |
| TopicPage | Page；专题有独立介绍、路由、SEO/权限和编排 | 介绍/精选关系随 Topic Revision；可引用多种类型，不复制正文 |
| Series | 建议版本化 Snippet，表示可多处复用的有序阅读集合 | 明确配置原生 Revision/草稿发布支持及权限，顺序随 Series Revision；若需独立栏目/路由再评估 Page，不提前建两份权威 |
| FeaturedCollection | 建议版本化 Snippet，复用首页/侧栏/作品精选 | 独立审批/发布是否启用需框架验证；父页面可固定已发布版本或跟随最新已发布，禁止跟随最新草稿 |

**当前框架事实：**Wagtail 8.0 官方提供 RevisionMixin、DraftStateMixin、WorkflowMixin 等可供 Snippet 组合的原生机制。Series/Collection 的实际组合、子关系序列化、权限、预览与发布传播仍须按安装版本进行集成验证；普通 Snippet 不会自动拥有全部能力。默认建议跟随最新已发布版本；这意味着集合发布后引用位置在失效缓存后更新，父 Page 不自动新增 Revision。若要求复现当年编排，则固定集合已发布 Revision，并保留该版本/引用；改绑需发布父页面。两种策略必须可区分，P4b 前确认默认值。

无论固定版本还是跟随版本，目标 Page 的公开状态与访问限制都即时复核，不因旧集合快照恢复其可见性。一个 Page 可同时进入多个专题/系列/集合，但仍只有一个正式 Page 身份。

### 15.4 目标删除、失效占位与版本传播

**已确认产品需求：**选择器只是入口，不能替代引用完整性和发布合同；草稿可引用未发布 Page，发布父对象不会发布目标。下面删除策略是**方案推荐**，P4 前须以原生 modelcluster/Revision 和删除收集器验证。

| 关系 | 所有者/发布权威 | 目标删除策略与理由 | 历史、更新与恢复 |
|---|---|---|---|
| Home 人工精选、Blog/Guide 手工相关、Topic 编排 | 父 Page 子关系，随父 Revision 发布 | 建议可空 FK `SET_NULL`，配稳定目标标识和编辑失效占位，避免一条推荐阻止原生删页 | 编辑人工顺序/覆盖配置须重新发布父；目标卡片跟随当前正式内容；历史恢复时缺失目标仍为失效项 |
| Series/FeaturedCollection 条目 | 版本化 Snippet 及其子关系 | 同类可修复空引用；是否有强制不可缺项的系列，另设发布校验，不先全站 PROTECT | 修改集合要发布集合；引用者按明确策略跟随已发布或固定版本 |
| 父 Page 引用复用集合 | 父 Revision 保存集合身份/传播策略；集合有自己的发布权威 | 建议保留被引用的集合/版本，活动引用用 PROTECT 或受控退役；不能级联删除引用它的 Page | 跟随模式发布集合后失效缓存即可传播，父不新建 Revision；固定模式须发布父改绑 |
| 固定集合 Revision | 父快照固定已发布版本，仍服从当前访问策略 | 明确保留 pin，防止 Revision 清理删除；裸 revision_id 不是保留策略 | 固定的是编排内容，不是永久公开资格；取消 pin 按保留政策 |
| 正文 Page 链接/内容选择 Block | SQL Revision 或 Mongo 字段版本 | payload 保留稳定引用；缺失时按 Block 规则显示安全占位/隐藏，禁止改写旧 Mongo payload | 新版本可修复；历史不悄悄重绑其他同 ID/同 slug 对象 |
| 封面/Gallery/媒体引用 | 父快照与公共资源引用记录 | 按第 5 节保护媒体，不套用推荐目标的 SET_NULL 自动回收 | 页面删除与媒体回收分离，历史证据仍保护旧文件 |

对 Page 的普通 FK 置空仅影响当前关系表，不能改写所有历史 JSON/Mongo；因此读取器需用稳定标识解析并校验目标是否仍存在，保存时规范化失效引用，提供授权编辑可修复的提示。失效占位只在后台显示必要信息，不向无权读者暴露旧标题。历史 JSON 中保留 target_id 本身不构成数据库 PROTECT；独立集合/固定版本若需历史保护，必须由保留记录覆盖，不能仅靠当前 FK。

撤销发布、转私有、移动导致权限变化时，前台在读取每个条目前复核当前访问，不等父对象重发；缓存和异步投影不能继续展示旧标题/封面。父预览只代表父编辑资格，读取未发布目标正文/私有卡片另需目标预览资格，不能借跨类型选择器扩大权限。

Page 的恢复是原生 Revision 恢复，不是“删除 Page 后一定能恢复”。目标已删即保持失效；重建同标题/URL 不自动重绑。复制父 Page、复制子树、别名与解除别名须测试内联顺序/覆盖字段、新旧目标映射、跨站限制和当前授权；批量删除不能绕过策略。**实现后待验收：**P4b 逐关系验证保存→预览→发布→目标撤销/私有/删除→父恢复→集合发布传播，检查 SQL、Revision JSON、缓存及前台；PROTECT/SET_NULL 和固定版本保留的可行性仍为技术待验证，不记为已实现。

### 15.5 首页六类场景与前台回归

**当前源码事实：**旧首页有栏目卡片轮播、单张 Banner 放在 carousel 容器、热门文章 masonry 网格，三者不能统称同一文章轮播。人工跨类型精选是新增需求。静态位置见 10，未运行浏览器验证。

| 场景 | 来源与修订性质 | 所有者/发布及回归断言 |
|---|---|---|
| 栏目/频道轮播 | 旧 BlogIndexPage 栏目卡片行为保留，扩为显式栏目选择/站点结构 | 人工关系归 Home Revision，自动栏目来源另标；不把栏目假充单篇文章 |

## 16. Content Discovery、Archive、Search 与 AI

Discovery 负责跨类型的正式候选集及统一元数据：Page/type_key、site、locale、正式日期/标题/摘要/URL、代次与访问条件。首页热门/最新/推荐、自动相关文章、归档、Feed 及公开 API 使用同一正式与访问合同；人工编排复用其卡片/验证能力，不被自动规则覆盖。Registry 不必将每个协议做成独立 App。

Archive 负责年份/月/时间线、筛选、分页和模板，不调用 Blog 专属 Service。支持全站、单类型和类型组合及站点/语言/日期过滤。P5 采用可重建、按发布代次幂等更新的年月汇总/查询投影，覆盖发布日期变更、移动、撤销、删除和权限变化；重建分批、断点和校验水位。请求不聚合扫描全库。公共汇总只统计公开内容，受限内容的数量也不能泄露；需要个性化计数时另定可负担策略。汇总是最终一致的，精确性/延迟作为验收条件，不假定所有 `.count()` 免费。

保留 Wagtail 原生搜索接口及 ES 后端扩展。正式索引按物理 index/alias 明确唯一写入者；建议公共 Outbox 拥有注册内容正式投影，原生自动更新仅用于明确独立的索引/后台用途，或经受支持方式关闭相应更新。P5 先核对当前 backend、modelsearch、信号、设置和重建命令，不能仅凭一个 `AUTO_UPDATE` 设置假定所有路径关闭，也不能影响必要后台搜索。重建/alias 切换也沿用相同权限/代次规则。

源码能证明旧原生 Page 与 Blog Outbox 两条链路并存，不能证明它们实际写了同一物理索引；生产环境配置、实际 index/alias 本轮未核实。新增类型通过 Registry/Projection 接入；Search 不依赖 BlogPublicationState。ES 延迟时按第 8 节批量校验当前 SQL 状态和版本，覆盖卡片文字、高亮及建议词，而非只校验 ID。

`content_ai` 公共部分负责模型调用、配置/权限、任务注册、提示词版本、任务状态、错误/超时和脱敏审计；类型策略提供博客元数据、指南摘要、专题介绍、作品描述等输入输出约束。Provider 只读取获授权内容，不把正文及敏感数据随意发给外部服务；执行需符合任务授权。生成结果是建议或原生草稿，保存/审核/发布仍走统一契约。资源模块不承担 AI 页面任务编排。

## 17. 媒体处理、实时业务与前端装配

| 层 | 职责 | 首版边界 |
|---|---|---|
| resources | Image/Rendition/Document/经验证的音视频实体，元数据、引用、上传授权 | 全站公共，不按 Blog 决定路径；不建万能 Asset 表 |
| Django Storage / MinIO | 按资源类型/策略持久化原件与派生文件 | 不决定页面发布、播放权限或转码完成 |
| Media Processing | 探测时长/格式、封面、可选转换 | 首版必要探测与已有格式兼容；HLS/DASH/多码率另评估 |
| Media Delivery | 当前授权、Range/播放器、缓存与短期 URL | 文档下载权限、视频 Range、签名失效边界需真实服务验证 |
| Embed | 第三方链接的解析/信任/渲染 | 保留已有 Embed，不强制下载为本地视频 |

当前 `STORAGES["wagtailmedia"]` 是公共 media 别名；新增 `audio`/`video` 不会自动使第三方模型按类型分流。需核验自定义模型、storage callable/字段、保存路径、chooser、后台与升级支持，选择有证据的扩展方式。第三方插件不能任意替换原生生命周期。

comments 关联通用 Page，保留回复/反应/审核/反垃圾；实时记录不随页面 Revision 恢复。页面禁评论或撤销后的读取/写入/保留规则、删除时级联或保留策略在 P0 合同设计、P7 实现前复核；不复制 Blog 专属 API。engagement 统一 Page 点赞/阅读/进度/统计，去重和时间窗口有明确规则；展示故障可回退计数缺失，访问判断不可回退放行。

base/home 的 URL、模板标签、上下文、CSS/JS 装配也须解耦：仅移动模型无法解除模板对 blog_tags/BlogImage 的依赖。按能力启用组件，停用可选 App 不应产生模板导入错误；公共资源、编辑器组件和相关静态依赖有稳定入口。必要的具体页面模板仍由其业务 App 负责。

## 18. 扩展验收与容量边界

中立第三种 Page（例如测试 KnowledgePage）应在自己的 App 中注册媒体、搜索、精选、归档、相关文章、可选评论、原生权限/Workflow；仅外置声明字段使用 Mongo。主要改本类型字段/面板/模板与装配，公共模块不新增具体类型分支；允许必要原生关系模型。逐项测试保存、预览、发布、撤销、历史恢复、访问过滤、可选模块失败及版本兼容，不能只检查目录/导入成功。

容量目标是一亿篇的长期研究边界。本轮没有任何容量测试。P1/P3/P5/P8 逐级测量 SQL Page 树路径/子树移动/原生别名扩散、Revision 保留、Mongo 版本增长、ES 索引/重建、归档汇总、媒体引用索引及备份恢复。数据档位、硬件/并发/冷热/采样窗口和 P95/P99/错误率必须记录；依据结果评估保留、分区/索引和树组织，不先宣称原生 Wagtail 无限扩展。

首轮源码依赖矩阵和治理记录、第二轮风险补强、P0 技术验证设计续批及实际检查分别见 [10](10-新站架构与AI团队审计报告.md) §§1～10、§11、§12。所有上述新协议、模型、页面和组件除特别标注旧事实外，均为尚未实施的目标设计。
